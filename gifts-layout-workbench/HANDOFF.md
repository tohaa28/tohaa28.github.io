## Критично: как устроен запуск

`launcher.js` создаёт fullscreen iframe и присваивает большой HTML в `frame.srcdoc`.

Внутри этой строки находится полноценный JavaScript proxy для gifts.ru.

Поэтому:

1. Любая вставка JS внутрь srcdoc требует двойного контроля кавычек.
2. Неэкранированная двойная кавычка внутри srcdoc может сломать внешний launcher целиком.
3. Именно это произошло после первого добавления даты заказа.
4. Исправление находится в commit `162a99613d030b686808179bddedd06a9513860e`.

Перед публикацией изменений launcher проверять:
- что строка `frame.srcdoc` не разорвана;
- что новые строковые литералы внутри встроенного скрипта безопасны;
- что cache-busting bundle совпадает в editor.html и launcher.js.

## Последние требования пользователя — считать действующими

### Стартовая страница заказов

- Заголовок: `Создать макет для заказа`.
- `МАКЕТЫ ЗАКАЗОВ` скрыт.
- `Вернуться к открытому макету` скрыта.
- Заголовок корзин:
  `Корзины и выбранные нанесения`
  + вторичный счётчик в скобках.
- Вторичный счётчик: 12px, обычный шрифт.
- Текст под корзинами:
  `Нажмите карточку заказа, чтобы перейти к созданию макетов по заказу.`
- Рядом с `Заказ №...` показывать дату оформления обычным шрифтом.
- Если дата не найдена — ничего не подставлять.

### При выборе артикула

Всегда сначала показывать `Шаблон целиком`.

Даже если найдено единственное поле — не открывать его автоматически.

После этого пользователь сам выбирает место нанесения.

### Навигация страниц

Если PDF 1-страничный:
- полностью скрывать стрелки;
- скрывать `Страница 1 / 1`;
- не оставлять пустой служебный блок.

Если PDF многостраничный:
- показывать штатную навигацию.

### Инструменты логотипа

`Добавить логотип в остальные поля` находится в верхней панели инструментов логотипа, сразу после `Добавить логотип`.

Из левого фрейма эта кнопка убрана.

### Alt+N

Окно настроек нанесений должно автоматически выбирать текущий вид нанесения.

Текущая реализация использует:
- `#method`
- `#orderTemplateSummaryText`
- выбранную `.article-choice.selected`
- `resolveMethod(...)`

Если появится ошибка в заказе с несколькими местами/методами, следующий правильный архитектурный шаг:
передавать в `installMethodAdmin` callback `getCurrentMethod`, который будет получать метод из активного поля/placement напрямую из состояния редактора.

## Другие неизменные требования проекта

- Не использовать Floot.
- Не переделывать Макетную в расширение Chrome.
- Авторизацию gifts.ru использовать существующую браузерную.
- При запуске перечитывать корзину с сайта.
- Заказы группировать по номеру.
- Вся карточка заказа кликабельна.
- В Step 1: артикул, название, тираж, фото товара, вид нанесения, точное место/код.
- Если артикул один — выбирать автоматически.
- Step 2 показывать после артикула.
- В Step 3 — инструменты размещения логотипа.
- Несколько полей могут иметь разные логотипы.
- Итоговый PDF должен содержать все размещения.
- Не растягивать изображения с нарушением пропорций.
- Поля свободной формы использовать как реальную форму.
- Сохранять возможность перехода в Редактор мокапов.
- Не ломать текущие сопоставления полей/фото мокапов.

## Что делать первым в новом чате

1. Прочитать этот HANDOFF.
2. Проверить текущий `main` и не предполагать, что он всё ещё равен указанному SHA, если пользователь продолжил работу.
3. Перед новой значимой правкой создать rollback branch.
4. Не откатывать изменения интерфейса, перечисленные выше.
5. Если пользователь сообщает, что Макетная снова не запускается — первым делом проверять синтаксис обоих `launcher.js` и последние изменения внутри `frame.srcdoc`.
