**18.11.2026 · MV3 v0.1.5 · feature/printcheck-vision-copy-v01 · только тестовые домены.**

## Проверенный источник (хранится ТОЛЬКО в приватной загрузке пользователя)

Сохранённая HTML-копия заказа (не публикуется) показала:
- одну native ссылку "Согласование макета" в li[data-itemid],
  на ней badge **8**;
- открытое g-modal[visible], связанное с конкретным oiid;
- 23 хронологических записи: 8 реплик и 15 системных событий;
- 27 доступных вариантов проблем, из них 2 currently checked;
- 4 g-gallery с **5 оригинальными изображениями**.
- В этом примере 0 ссылок a.j_maketadjusting_attachment:
  скриншоты находятся в g-gallery.shadowRoot -> section picture img.
- Отдельный анонимный файл диагностики давал rows_scanned=0
  при 61 строке, все NOT_SCANNED. Это не доказывает отсутствие переписки,
  а показывает, что прежний одноразовый структурный обход не был запущен.

**ВАЖНО:** сам HTML заказа, имя клиента, содержимое сообщений,
пути изображений и ID не входят в публичный GitHub, fixtures и логи.

## Новый маршрут пользователя

1. Установить изолированное тестовое расширение Chrome MV3 **v0.1.5**.
2. Открыть авторизованную страницу
   http://psk.testgifts.local/devorders (любые доступные фильтры).
3. В Vision Check нажать **«Собрать согласования из всех заказов»**.
4. Расширение берёт точные ссылки на карточки из строк текущей таблицы,
   удаляет повторяющиеся ссылки и последовательно открывает разрешённые
   http://testgifts.local/private/order/<номер> во временных вкладках.
   Контентный скрипт автоматически обходит только артикула с цифровым
   счётчиком >1, нажимает штатные "Согласование макета" и, если нужно,
   штатную вкладку "Обсуждение". Не вызывает POST, не сохраняет
   согласование и не отправляет комментарий.
5. В каждом заказе отдельно локально сохраняется
   vision-private-approval-evidence-<номер>.json:
   checked проблемы (вид нанесения, место), полный текст/порядок
   обсуждений, события, метаданные вложений, SHA-256 и статусы GET.
6. По изображениям и PDF формируются приватные локальные
   vision-private-approval-attachments-part-*.zip. Скриншоты
   извлекаются из открытых Shadow DOM галерей; оригиналы, не навигационные
   миниатюры и не фотографии авторов.
7. **«Остановить согласования»** останавливает после текущего заказа.
   **«Отчёт согласований JSON»** содержит только счётчики/коды статусов.
   Старый «Обсуждения JSON» — отдельно, только структурная диагностика.

## Сетевые ограничения

Manifest v0.1.5 дополняет http://files.testgifts.local/* разрешением
для чтения оригинальных скриншотов; не разрешает production gifts.ru.
Worker принимает GET к /maketadjusting/<id>/<order>/<item>/<filename>.<image>
только с контентного скрипта именно заказа <order>. Подмена order,
запрос к другому path, query, иной хост/протокол или POST => отказ.
Native бинарные вложения читаются прежним точным GET на testgifts.local.
Размер одного файла не выше 16MB; архивы ограничены 24MB/часть.

В приватный JSON не записываются прямые URL галерей. Они доступны только
непосредственно в памяти страницы, привязаны к статье и сообщению и
исключены из анонимной диагностики. SHA-256 доказывает идентичность
сохранённых байтов, но не подлинность самого источника.

## Доказательства и ограничения

- Модуль: vision/orders/approval-inline-images.mjs.
- Синтетические Node проверки: привязка скриншотов к заказу/артикулу,
  запрет чужого URL и удаление URL из JSON, исправность ZIP и SHA.
- MV3 worker: только разрешённые URL и вкладки локальной тестовой сети.
- Синтетический браузерный тест от /devorders до приватного ZIP/JSON:
  tests/printcheck-vision-approval-queue.browser.mjs.
- Реальный authenticated end-to-end запуск на testgifts.local пока
  **не подтверждён**; копия HTML подтверждает структуру DOM, но
  серверный ответ на GET вложения и настройки Chrome могут отличаться.
- Реальное сопоставление замечаний с версиями PDF/методом печати/ROI
  требует отдельной проверки и экспертной разметки. Никаких автоматических
  позитивных обучающих меток не создаётся: training_ready=false,
  production_approved=false.
- Производственная Макетная и main (кроме изолированной публичной
  папки предпросмотра при успешном workflow) не меняются.
