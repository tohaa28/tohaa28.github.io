## Привязка и ограничения

Метод берётся из существующего `field.orderMethod`/сопоставления `oo(fieldIndex)`, затем из заказа или ручного ввода. Не применяется глобальный номер application как локальный printN. Несколько разных кодов или неизвестный код дают `manual`, без угадывания. Подложка распознаётся только по явному тексту места; неизвестные условия не считаются ложными.

Проверяются: текстовые объекты, SVG/PDF-эффекты, реальные размеры и DPI (включая встроенный растр и масштаб шаблона), исходные RGB/CMYK-операторы PDF, известная сумма CMYK, измеримые SVG-примитивы/обводки, число цветов простого SVG и выход за точный контур поля. Цветовая палитра заказа, ICC/Pantone, плотности красок, сложные контуры, перекрытия, высота букв в кривых и скрытые PDF-слои не сертифицируются. Частичная поддержка указывается в отчёте.

Оценка минимальных пробелов и одиночных элементов по изображению даёт `manual` и необязательную подсветку. Она не заменяет измерения исходного вектора: сглаживание, растр, фон, перекрытия и дискретизация могут менять силуэт. При неоднородном масштабировании или перекрытии измерения обводок также требуют проверки.

Охранное поле изделия и линия реза не подменяются границей поля нанесения. Нормы отступов, вылетов, текстур и материалов всегда отображаются; проверка без соответствующей геометрии остаётся ручной. Обрезка не скрывает нарушения вне поля.

Проверка выполняется один раз при загрузке для свойств исходника, а требования и размеры пересчитываются для каждого размещения. Логотипы/заказы не отправляются внешним сервисам. Исходники и геометрия полей не меняются.

## Диагностика и экспорт

В шаге 4 доступны подробный отчёт и JSON. `window.gwbLogoPreflight` — копия отчётов без методов изменения редактора. Экспорт проекта сохраняет отчёты. Для каждого результата указаны идентификатор, статус, источник и при наличии измерение/норма/область. `productionApproved` всегда false. Ошибки используют прежнее подтверждение скачивания; изменения сбрасывают подтверждение.

## Проверки

`node --test tests/*.test.mjs`; браузерный сценарий в `.github/workflows/test-direct-workbench.yml` вызывает прежний `verifyPdfLabels` и новый `verifyLogoPreflight`. Последний проверяет реальные SVG/PDF, масштаб, подложку, два метода одного артикула, диагностику, удаление/замену и подтверждение экспорта. Публикация запускается только после reusable test job и использует тот же github.sha.

- Интеграция в существующий compiled editor оформлена воспроизводимым `tools/patch-artwork-preflight.mjs`: он применяется из `tools/build-launcher.mjs` до тестирования/публикации. SHA-256 исходного и итогового JS проверяются; при изменении исходного bundle сборка останавливается для повторной проверки патча. Большой исходный bundle с PDF.js в ветке остаётся прежним, а опубликованный bundle содержит проверенные изменения. Это устраняет передачу неизменённых библиотек в запросе GitHub и делает патч отдельно обозримым. Для локального editor.html сначала выполнить `node tools/build-launcher.mjs`.
