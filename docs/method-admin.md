# Административные настройки нанесений

Открытие — Alt+N (физическая клавиша N, работает и в русской раскладке), повторное нажатие закрывает окно. Вход admin/admin. При обычном запуске окно закрыто; авторизация не сохраняется между открытиями. Escape, крестик и «Отмена» закрывают панель без применения черновика. Сохранение применяет настройки к текущим размещениям и их диагностике.

Изучен чат «Исправление HTML JavaScript» (6a9ffee3-4e74-83eb-8353-05e787a36242) и приложенный index (2).html: скрытые настройки при запуске, открытие по горячей клавише, проверка хеша пароля, отдельный draftConfig, сохранение/отмена. Здесь Alt+N сразу открывает вход, согласно текущему запросу пользователя. Панель реализована как dialog, с принудительным display:none для закрытого состояния; её авторизация локальная, не серверная.

Параметры хранятся централизованно в GitHub: исходный файл `method-settings.json` ветки `gifts-layout-workbench-mockups-source` репозитория `tohaa28/tohaa28.github.io`. Публичная копия публикуется по адресу `https://tohaa28.github.io/gifts-layout-workbench-mockups/method-settings.json`. Все пользователи получают общий JSON автоматически при запуске и обновляют его в открытой Макетной примерно раз в 2 минуты. `localStorage` больше не участвует в проверке; прежнее содержимое `gwb-method-settings-v1` доступно только по явной кнопке переноса в черновик. Экспорт/импорт JSON сохранены. Все методы и параметры проверяются по схеме, отрицательные/бесконечные пороги, неизвестные коды, неизвестные проверки и неверные типы отклоняются. Ошибка хранилища не выдаётся за успешное сохранение.

Исходная PRINT_REQUIREMENTS остаётся неизменной и соответствует документированной карте gifts.ru. `configureRule(effectiveRule(...))` применяет пользовательские overrides последними. Охранное поле, включая длинную/короткую сторону, по умолчанию 0 мм для всех 92 кодов. Пользовательское положительное охранное поле измеряется от границы выбранного нанесения. Старые общие guard/minDpi в скрытом подробном редакторе заменены настройками по коду и больше не добавляют отдельные блокировки экспорта.

Есть общий выключатель метода и отдельные группы: шрифты, эффекты, скрытые объекты, dpi, цветность, позитив, негатив, отдельные элементы, PrintCheck, граница поля, охранное поле, вылеты, контуры, дополнительные условия. Отключённые findings не участвуют в блокировке экспорта; отчёт явно указывает отключение/пользовательские настройки и не становится productionApproved. Структурная проверка соответствия мест заказа и printN остаётся независимой.

Изменение настроек обновляет результаты и кнопки экспорта. Отключение PrintCheck/метода удаляет ключ размещения из очереди, отменяет текущий worker и убирает устаревшие маркеры. Изменённые пороги входят в ключ кеша. Отключение позитивов/негативов/отдельных объектов передаёт в анализ нулевой порог соответствующего типа.

Проверки: 60 unit tests; browser regression — неверный/верный вход, 92 кода, черновик/отмена, изоляция методов, guard 0 и override 1000, цветность и экспорт, выключение метода и worker, import/export/невалидный JSON, загрузка сохранённой конфигурации в новом окне, Alt+N/Escape. Прежние field/clip/printN/rotation/zoom тесты сохранены.

## Тип исходного макета: вектор или растр (2026-10-14)

Для каждого кода нанесения в «Параметрах» появился отдельный селектор **«Требование к исходному макету»**:
- **По исходным требованиям (вектор или растр)** — значение без администраторского ограничения. Не приписывает gifts.ru запреты, которые не были явно подтверждены для кода.
- **Допускается вектор и растр** — явное разрешение любого типа исходника.
- **Только вектор — запрет встроенного растра** — растровые PNG/JPEG и встроенные изображения в SVG/PDF вызывают ошибку проверки `artwork-type` и блокируют экспорт до исправления исходника либо изменения правила администратором.

Администратор выбирает нужный код нанесения и сохраняет его отдельную настройку. Формат настроек остаётся `version:1`: новая необязательная `methods[code].artworkPolicy` может быть `"any"` или `"vector-only"`; старые JSON-файлы/локальные настройки читаются без миграции. Отдельная группа проверок **«Вектор / встроенный растр»** позволяет при необходимости отключить именно этот контроль. При выключенной целиком проверке нанесения он тоже не выполняется.

Проверяется **загруженный исходный файл нанесения**, а не растровое превью редактора и не фотография товара. Классификация: `vector` (SVG/PDF без обнаруженного растра), `mixed` (SVG/PDF со встроенным растром), `raster` (исходный PNG/JPEG), `unknown` (не удалось достоверно выяснить тип). Если для метода нужен чистый вектор, `mixed` и `raster` дают ошибку; `unknown` требует ручной проверки и **не подтверждает** соответствие. Для остальных режимов растр допустим, но продолжает проверяться по DPI, цветовому режиму и прочим требованиям.

Определение основано на DOM SVG и исходном PDF.js operator list, включая операции изображений, масок и inline-images, а не на имени расширения. Вложенный SVG как `<image>` без отдельного разбора классифицируется осторожно (не сертифицируется как чистый вектор). Неизвестные PDF-паттерны и сложные контейнеры могут потребовать ручной инспекции; автоматическая проверка никогда не гарантирует пригодность по всем остальным требованиям производства.


## Централизованное хранение требований (15 октября 2026)

Серверный источник: `method-settings.json` в исходной GitHub-ветке. Чтение публичное и не требует токена. Изменения администратора выполняются только по GitHub Contents API после авторизации токеном **fine-grained** с доступом к репозиторию `tohaa28/tohaa28.github.io` и разрешением **Contents: Read and write**. Токен вводится непосредственно перед сохранением в поле окна «Настройки нанесений»; приложение не сохраняет его в локальном хранилище или в JSON.

После нажатия «Сохранить настройки на сервере» программа перечитывает актуальный GitHub-файл и проверяет SHA и неизменность предыдущей редакции. При конкурентном изменении другой администраторский черновик не перезаписывает сервер — требуется нажать «Обновить с сервера», затем повторить правку. Успешное сохранение подтверждается идентификатором GitHub-коммита и немедленно применяется в открытой Макетной. Изменение файла запускает публикацию через GitHub Actions, после чего оно доступно всем. На остальных открытых клиентах есть автоматический повторный запрос настроек и обновление диагностики.

При отсутствии связи с сервером программа показывает ошибку **«Общие настройки не загружены»** и блокирует экспорт до восстановления связи вместо применения устаревших локальных настроек. Поскольку GitHub Pages — статический хостинг, права на запись удостоверяются GitHub-токеном, а не локальным паролем админ-панели.

Для переноса прежних параметров: открыть настройки → нажать «Загрузить прежние локальные настройки» → проверить содержимое → ввести GitHub token → нажать «Сохранить настройки на сервере». До подтверждённого сохранения никакие прежние пользовательские значения не распространяются на других операторов.
