# C3B.3.P — получение макетов через карточку тестового заказа

Дата: 2026-11-17. Работа строго в \`feature/printcheck-vision-copy-v01\`, PR #4 остаётся DRAFT.

## Уточнение пользователя

Таблица \`http://psk.testgifts.local/devorders?status=140\` **не содержит исходных файлов**. Сначала нужен переход с кликабельной строки на карточку конкретного заказа, потом способ получения файлов полностью аналогичен рабочей «Макетной», но на доменах тестовой сети. Нужны преимущественно **векторные макеты**, растровые также поддерживаются.

## Проверенный исходным кодом «Макетной» протокол (не догадка)

В \`direct-mode.js\` на исходном Gifts используются следующие GET/read-only шаги:

1. \`GET /private/order/{orderNumber}\`. В полученном HTML ищется внутренний ID заказа в \`#j_cart_host[data-orderid]\`, \`.cart-order[data-orderid]\`, \`.j_add_maket[data-orderid]\`.
2. \`GET /ajax/gifts/order?action=makets_popup&oid={internalId}\`. Ответ может быть JSON \`{html: "..."}\` либо HTML.
3. В разделе «Загрузка макетов» исходные клиентские файлы имеют ссылку \`a[data-maket="true"][href]\`, где URL должен совпадать с \`/cart/act/mda?oid={internalId}&id={fileId}\`. При несовпадении \`oid\` ссылка не может быть скачана.
4. В разделе «Шаблоны макетов для выбранных нанесений» есть \`/drawing?action=getOrderItemPdf&orderitemid={orderItemId}\`. Это **конструкторы и эталонные документы**, а не заказанные клиентом макеты! Их нельзя смешивать с файлами клиента для обучения.
5. Для анализа клиентского макета источник \`/cart/act/mda\` загружается только методом GET, без \`upload_makets\`, \`j_delete_maket\`, сохранения заказа или иных мутаций.

Этот протокол извлечён из уже существующего кода «Макетной». **Он не подтверждён на живой тестовой сети**, т.к. ни браузерный connector данной сессии, ни GitHub CI не имеют подтверждённого доступа к локальному серверу пользователя.

## Новые модули

- \`vision/orders/order-page-discovery.mjs\` — статическое чтение \`a[href]\`, \`data-href\`, \`data-url\`, \`onclick\` без исполнения JS, поиск явного номера заказа в первой ячейке как fallback, затем GET карточки заказа и popup. Используется только строго разрешённое \`http://psk.testgifts.local\` / \`http://testgifts.local\`. Браузерный CORS и cookies сохраняются честно; их нельзя обходить незаметно.
- \`vision/orders/overlay-entry.mjs\` — приоритетно вызывает модуль карточки, после чего проверяет исходные клиентские файлы и отображает отдельный статус в каждой строке. Не отправляет клики от кнопок/форм Vision родительскому \`TR onclick\`, чтобы не возникало незапланированных переходов со страницы таблицы. Векторный SVG проверяет исходную геометрию, PDF остаётся MANUAL до создания source-faithful парсера, растровый MLP работает лишь как исследовательский.
- \`vision/orders/row-scanner.mjs\` — принимает расширение/имя файла из проверенного popup, так как URL \`/cart/act/mda\` не содержит \`.svg\`/\`.pdf\`.
- \`vision/orders/local-training-zip.mjs\` — при явном подтверждении экспортирует только оригиналы из верифицированных загрузок клиента; конструкторы и чужие вложения не входят. Копии исходников не попадают в публичную ветку. Метки уровня строки не утверждают ROI/печатные нормы.
- \`tests/printcheck-vision-order-detail.test.mjs\` и \`tests/printcheck-vision-order-detail.browser.mjs\` — проверяют последовательность GET, внутренние order IDs, выделение конструктора, отказ на CORS или ошибке карточки, блокировку production \`gifts.ru\`, отсутствие POST/удаления и сохранение состояния открытой таблицы. Только синтетический HTML / SVG / PDF.

## Ограничения сети

Код исполняется в браузере в авторизованном тестовом домене. Если карточка или файл фактически расположены в другом разрешённом домене \`testgifts.local\`, браузер может заблокировать cross-origin response без \`Access-Control-Allow-Origin\` и \`Access-Control-Allow-Credentials\`. Это будет \`MANUAL: ORDER_DETAIL_FETCH_OR_CORS_FAILURE\` или \`TEST_SUBDOMAIN_CORS_OR_AUTH_REQUIRED\`. **Не делать невидимых обходов безопасности**. Прямые URL на \`gifts.ru\` и посторонние локальные хосты запрещены.

Для диагностики неизвестного DOM без утечки заказов добавлены только счётчики в \`Диагностика таблицы\`: наличие явных order href, data атрибутов, статического onclick, числового первого столбца, неоднозначных/неразрешённых строк. Этот отчёт не содержит номера заказа, HTML-код, ссылки, cookies или оригинальные файлы.

## Локальный тестовый стенд Windows

Подготовлен код \`tools/vision_local_lab.py\` и \`tools/install-vision-local-lab.ps1\`: после самостоятельного запуска на Windows устанавливают \`D:\VisionCheckLab\`, принимают локальный ZIP из экспертно размеченных строк, проверяют SHA-256/zip traversal/файловые сигнатуры и сохраняют исходники в приватную папку со SQLite-индексом; предоставляют read-only панель на localhost и CLI для разметки ROI. Сетевой передачи нет. Физически создать каталог на пользовательском D: из текущего облачного сеанса невозможно — инструкция и скачиваемый пакет в \`docs/VISION_LOCAL_LAB_SETUP_RU.md\`.

## Вектор и обучение

Не считать PDF-оригинал подходящим для автоматического обучения, пока его исходные CTM, ColorSpace, spot, прозрачность, clipping, page/ROI и полигональные границы не проверены независимым парсером. Для пригодного обучения нужны согласие на тестовые файлы (пользователь уже дал), **подтверждённая ROI-разметка** технолога, достоверный физический размер нанесения, хеши, семейные группы train/test и независимое подтверждение результатов. В текущем архиве \`training_ready:false\` и в БД \`approved_for_training=0\`.

Рабочая «Макетная» неизменна. Не сливать экспериментальный PR в production до проверки реальных тестовых заказов и качественной оценки.
