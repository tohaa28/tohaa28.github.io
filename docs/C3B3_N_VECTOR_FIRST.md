# PrintCheck Vision — C3B.3.N: приоритет проверки исходного вектора

Дата: 2026-11-17. Изолированная ветка `feature/printcheck-vision-copy-v01`, PR #4 DRAFT. Это **исследовательский** режим. Рабочая «Макетная» и производственная проверка не изменяются.

## Главный принцип

Большинство реальных производственных макетов приходит в PDF/SVG и других векторных форматах. Геометрические размеры линий, негативных промежутков, перемычек, отверстий и пересечений необходимо вычислять из **исходных контуров**, а не из растрированного изображения. Растровый AI предназначен для исходных bitmap, недостоверных векторов и вспомогательного сопоставления; он не должен заменять измерения вектора.

## Выполнено в этом цикле

- `vision/geometry/svg-local-vector.mjs` — строгий локальный XML→SVG DOM→геометрия, использующий существующие `svg-dom-vector-bridge.mjs`, `svg-path-subset.mjs`, `vector-corridors.mjs` и опциональные `curved-normal-probes.mjs`.
- Измеряет в мм, объявленных в исходном SVG `width/height` + `viewBox`. Кривые C/Q/S/T/A адаптивно аппроксимируются с погрешностью 0.002 мм, сохраняют исходный векторный смысл. Объекты `path` с групповой affine transformation обрабатываются до измерений.
- Для браузерного режима `vision-vector.html` — локальная загрузка SVG, synthetic demo, независимый от bitmap список кандидатов ширины положительных линий и отрицательных пробелов, безопасный Canvas Path2D предпросмотр. Предпросмотр **не является источником измерений**.
- JSON отчёт содержит измерения/неопределённость/координаты, но не содержит исходных байтов SVG и `d` атрибутов. Размеченный SVG сохраняется локально как редактируемая копия исходных путей с цветными кругами-кандидатами (т.е. **этот** файл по замыслу содержит исходный вектор).
- `index.html` и панель Vision теперь предлагают векторную проверку **перед** растровой нейросетью; растровый модуль не удаляется.
- `tests/printcheck-vision-vector.browser.mjs` — проверка реальной DOMParser/Path2D/модулей в desktop/mobile Chromium: synthetic gap 0.12 мм, экспорт SVG и JSON, отказ на script, DOCTYPE/XXE, external image, CSS, stroke, fonts/неподдерживаемых тегах без сетевых запросов. Публикация только в отдельный каталог `gifts-layout-workbench-vision/`.

## Поддерживаемое подмножество и безопасность

SVG: только допустимый строго разобранный XML, правильный namespace, физические mm/cm/in/pt с uniform viewBox, закрытые `path`, одноцветные `fill=#RRGGBB`, `g` transforms и прозрачность **не допускается**. Дополнительные криволинейные пробы включаются вручную. Неперекрывающиеся однотонные RGB-заливки разных цветов допускаются **только для независимых исследовательских измерений каждого цвета**. Любое перекрытие или касание между разными цветами, неизвестный overprint/knockout, текст/шрифты, обводки, CSS, clip, opacity, mask, filter, embedded/image/external/use/DTD/entities и неподдерживаемая SVG структура → **MANUAL**. Никакого частичного утверждения, если хоть один элемент потерян.

Выходные поля `production_approved`, `geometry_proven`, `print_scale_proven`, `actual_artwork_placement_scale_proven` всегда FALSE. Даже успешный разбор в мм по SVG не удостоверяет связку `order → SKU → constructor → print slot → logo placement`. Без доверенного источника размеров и множителя размещения нельзя сопоставлять абсолютные числа с технологическими порогами Gifts.ru. Отсутствие кандидатов ничего не доказывает.

Вход ограничен 256 КБ UTF-8 и бюджетами геометрии (128 путей, 768 сегментов, ограничение глубины XML и вложений, максимум 100 кандидатов). Парсер работает с изолированным XML DOM, не добавляет исходные узлы в текущую страницу, не вставляет HTML макета и не обращается к сети. Никакие реальные макеты или приватные заказные evidence не коммитить.

## Не завершено: следующий цикл N2 и P1

1. **N2 (первая ступень реализована):** `vision/geometry/svg-ink-forms.mjs` разделяет строго **неперекрывающиеся** однотонные SVG path по отображаемому RGB цвету, измеряет каждый набор самостоятельно, сохраняет `source_rgb_ink` у каждого кандидата. Если габаритные прямоугольники красок пересекаются или касаются — MANUAL, даже когда реальные фигуры внутри не соприкасаются (консервативный отказ). Отображаемый RGB **не доказательство Pantone/spot или соответствия печатной форме**. Следующая ступень: доказанный CMYK/spot и разрешённое наложение/overprint/knockout, отсутствие потери объектов, полнота реальной печатной формы.
2. **P1 (важнейшее):** настоящий PDF content interpreter с изначально сохранёнными ColorSpace/CTM, несколькими filled/stroked path, fonts-to-outlines, clipping, transparency, ICC/DeviceN/Separation. Пока PDF.js raster normalizes CMYK и часть операторов, **сложный PDF не принимается автоматически**. Требуется полное покрытие операторов или консервативный MANUAL; нельзя выдавать approval, измеряя только часть векторов.
3. Связать документный масштаб SVG/PDF с подтверждённым размером размещения в заказе и оригинальными байтами, сохранить source SHA/signatures вне публичного репозитория.
4. Для растровых макетов оставить MLP/segmentation в качестве независимого режима. Для обучения общего vector+raster QA набрать приватную экспертную выборку двумя технологами, пересмотреть реальные precision/recall по видам нанесения, исключить family leakage.

## Проверки и источники

- Браузер: `node tests/printcheck-vision-vector.browser.mjs`; требуется Playwright Chromium, синтетические SVG.
- CI: `.github/workflows/publish-printcheck-vision-preview.yml` включает синтаксис, браузерный тест и копирование ровно необходимых geometry-модулей.
- MDN DOMParser (изолированный XML и запрет вставки пользовательского дерева в страницу): https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString
- MDN Canvas Path2D fill / evenodd (исключительно для визуализации): https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/fill
- SVG2 Paths: https://www.w3.org/TR/SVG2/paths.html

## Дополнение N2 — строгая независимость цветов

- `1cdf4f3a`: `svg-ink-forms.mjs` группирует до восьми разных `#RRGGBB` исходных заливок в независимые геометрические исследовательские наборы без смешивания пикселей, с общим бюджетом 768 сегментов. Для каждого цвета заново прогоняет исходный `inspectSvgTree` на своей безопасной копии XML DOM; исходный файл не изменяет. Пересечение AABB между разными цветами => MANUAL, поэтому непроверенный knockout/overprint не может тихо пройти.
- `ce0e3939`: подключение к `svg-local-vector.mjs` только когда старый проверенный парсер отказал с `SVG_DIFFERENT_INKS_REQUIRE_SEPARATION`, в других случаях прежний fail-closed контракт сохраняется. JSON содержит `ink_forms` и `source_rgb_ink`, `inks_verified_as_print_spots=false`.
- `1f1c2424`, `47b920ed`: браузерные regression cases на раздельные исходные цвета и отказ при их наложении; `36b4f1e6`: CI копирует новый изолированный модуль.
- Вне этого подмножества реальные CMYK, Pantone/spot, ICC, обводки и сложные PDF не считаются проверенными; полноценный PDF parser и независимая геометрия остаются следующим приоритетом.
