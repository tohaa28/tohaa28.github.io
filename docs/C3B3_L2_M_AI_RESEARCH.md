# PrintCheck Vision — C3B.3.L2 + M0: исходные цвета PDF и исполняемый AI-прототип

**Дата:** 2026-11-17. **Статус:** экспериментальный. Источник — только \`feature/printcheck-vision-copy-v01\`; PR #4 остаётся DRAFT, Issue #5 OPEN. Основная Макетная, её JS и реальные заказы не изменяются.

## C3B.3.L2 — диагностический разбор PDF до PDF.js

\`vision/raster/pdf-source-color-audit.mjs\` — ограниченный read-only лексический анализатор PDF 1.x. Он читает только один простой открытый ASCII stream, разбирает имена с PDF \`#XX\` escape, комментарии, числовые операнды и операторы \`rg/RG\`, \`g/G\`, \`k/K\`, \`cs/CS\`, \`sc/scn/SC/SCN\` и базовые геометрические операторы. Возвращает **диагностику исходных** DeviceRGB, DeviceGray, DeviceCMYK и NamedColorSpace. Именованные цвета, ICCBased, DeviceN, Separation, сложные ресурсы и неподдерживаемые потоки остаются MANUAL. Custom spot-имена в ответе скрываются.

Это **не** полноценный валидатор PDF xref, PDF color pipeline или независимое color proofing. Статус \`SOURCE_COLOR_DIAGNOSTIC_ONLY\`, даже когда цвет DeviceRGB, никогда не является разрешением на печать. Исходный строгий PDF rerender allow-list из C3B.3.K не расширяется. Никакие данные заказов не извлекаются.

Проверка: \`node --test tests/printcheck-vision-pdf-source-color-audit.test.mjs\`.

## C3B.3.M0 — работающая нейросетевая оценка узких элементов

Новая отдельная страница \`vision-ai.html\` и модуль \`vision/ai/synthetic-feature-model.mjs\` реализуют *фактический* inference нейросети (8 входных признаков, 12 tanh нейронов, сигмоидный выход) **полностью локально в браузере**.

Вход: локальный PNG/JPEG/WEBP до 20 MB; декодирование браузером с ограничением размера и уменьшением рабочей копии до 700 px по большей стороне. Сегментация по alpha, автоматически выбранному угловому фону или вручную выбранной пипеткой краске. Для каждого подходящего центра 9×9 патча извлекаются пространственные признаки. Нейросеть прогнозирует узкую печатную линию; для пробелов используется инвертированная область между печатными границами. Кандидаты группируются в области и показываются красной/жёлтой маской.

Доступны синтетический пример, чувствительность цвета, отдельная проба краски, визуальное наложение и экспорт локального JSON с координатами кандидатов. В JSON **нет байтов загруженного изображения**. Данные не передаются на сервер, \`connect-src 'none'\`. Параметр ширины в мм — **только самозаявленное число** и не доказывает подлинный физический масштаб заказа.

### Источник обучения, качество и пределы

Веса созданы в локальной Python/PyTorch среде из искусственных 9×9 патчей: линии и пробелы различной ориентации, ширины и случайной геометрии; классы «узкий» и «неузкий». Отдельная *синтетическая* validation-выборка 3000 патчей показала accuracy 0.99733 при пороге 0.5, precision 0.99921 и recall 0.99219 при пороге 0.75. **Эти цифры нельзя переносить на настоящие макеты.** В модели нет настоящих размеченных производственных данных, не доказана адаптация к антиалиасингу/градиентам/фотографиям/тонким полутоновым сеткам и типам печати.

Основной риск: низкое разрешение входа и принудительное уменьшение до 700 px могут уничтожить мелкую геометрию, а неравномерный фон или несколько красок нарушают бинаризацию. Это сканер **подозрительных локальных участков**, не proof of absence, не certified mm и не производственная сортировка OK/ERROR. Модуль не обучается на загруженных файлах и не сохраняет их.

Каждый ответ содержит \`production_approved:false\`, \`physical_scale_proven:false\`, \`real_world_accuracy_proven:false\`. При пустой или неоднозначной маске возвращается MANUAL.

Проверка: \`node --test tests/printcheck-vision-synthetic-ai.test.mjs\`; браузер: \`node tests/printcheck-vision-ai.browser.mjs\` с Playwright Chromium.

Публикация выполняется отдельным workflow только в каталог \`gifts-layout-workbench-vision/\` GitHub Pages. Не публиковать PR #4 в основную Макетную. URL экспериментального анализатора: https://tohaa28.github.io/gifts-layout-workbench-vision/vision-ai.html (использовать после зелёного publish CI).

## Следующая задача M1 — реальная геометрическая калибровка и независимая оценка

1. Изолировать AI-инференс в Worker с лимитами времени и памяти; избежать блокировки UI.
2. Подключить текущий *реальный* raster-preview активного редактора к AI через локальную передачу данных, не раскрывая авторизованную сессию Gifts.ru другому origin; утвердить безопасность передачи.
3. Отделить стабилизированную пиксельную сегментацию от подтверждённого физического размера, завести реальные независимые свидетельства scale/field/logo.
4. Подготовить закрытую экспертную выборку хороших/плохих макетов: два технолога, blind-control ROI, раздельная оценка false positives/false negatives по видам печати, исключить пересечения исходных семейств между train и test.
5. Только затем обучить нейросеть на реальных размеченных образцах и настраивать технологические пороги. Любой unsupported PDF/SVG/цвет/ICC либо неизвестное поле → MANUAL, не OK.

Это исследовательский CPU-прототип, а не обещание подтверждённой точности или готовой автоматически работающей производственной системы.
