# Vision Check C3B.3.O — тестовые заказы в локальной сети (17.11.2026)

## Запрос и границы

Пользователь дал разрешение **скачивать тестовые макеты из внутренней тестовой сети и использовать их для проверки и обучения**. Главный веб-интерфейс: \`http://psk.testgifts.local/devorders?status=140\`; родительский \`http://testgifts.local/\` — другой origin. Доступ к LAN есть у браузера пользователя, но **нет подтверждённого доступа у GitHub Actions, сервера GitHub Pages и среды ChatGPT**. Никакие реальные документы не были получены или обработаны удалённо; все текущие тесты используют синтетический HTML/SVG/PDF/PNG.

Ветка: \`feature/printcheck-vision-copy-v01\`, PR #4 DRAFT. Не сливать в production. Исходные файлы, приватные URL, номера заказов, сессионные cookies и экспертные метки не отправлять в публичный репозиторий.

## Реализовано

1. \`vision/orders/row-scanner.mjs\`: точная проверка \`http:\`, hostname \`psk.testgifts.local\`, route \`/devorders\`; поиск кандидатов на макеты в \`table tr\`, \`[data-order-id]\`; только same-origin ссылки; независимая последовательная загрузка до 32 файлов за сеанс, максимум 8 на строку, 80 строк, 16 MB на файл, тайм-аут 15 с; streaming ограничитель, запрет redirects и передачи credentials другому origin.
2. Для SVG — существующий **source-vector** строгий анализ в мм: замкнутые однотонные пути, curves/affine и раздельные неперекрывающиеся RGB формы. Итог — только \`RESEARCH_ONLY\`, документные мм не являются доверенным масштабом заказа. Для растров PNG/JPEG/WEBP — существующий синтетический MLP на уменьшенной до 300px рабочей копии (не утверждённая точность). PDF даже после валидной сигнатуры — \`MANUAL: PDF_VECTOR_PAINT_PIPELINE_NOT_VERIFIED\`, без ложного утверждения «годен»; CDR/EPS/AI/PSD/TIFF/ZIP — \`MANUAL\`, пока не реализован безопасный parser.
3. \`vision/orders/overlay-entry.mjs\` — настоящая колонка «Vision» по строкам заказов, кнопки «Проверить строку» / «Проверить макеты», суммарный статус, метка эксперта, локальный JSON-экспорт; повторное открытие закладки закрывает overlay, исходная таблица не заменяется. Всё выполняется **после явного нажатия** пользователя, без автозагрузки и фоновой синхронизации.
4. \`vision-local-orders.html\` — отдельная страница установки закладки, ограниченной ровно локальной тестовой таблицей; исходный скрипт бандлится в один classic \`vision-order-overlay.js\`, чтобы загрузить его на HTTP странице с публичного HTTPS GitHub Pages (если CSP допускает). Код стороннего сайта не модифицируется.
5. \`diagnoseTestOrderTable\` + кнопка «Диагностика таблицы»: локальный JSON только со счётчиками HTML-таблиц, строк, кнопок и типов ссылок. Не включает HTML, URL, текст строк, идентификаторы заказов, исходные байты. Можно безопасно прислать в следующий чат, чтобы уточнить DOM-адаптер, если реальные заказы устроены не как синтетические.
6. \`tests/printcheck-vision-local-orders.test.mjs\`: отрицательные границы origin, redirect, размер файла, PDF и невалидные сигнатуры; \`tests/printcheck-vision-local-orders.browser.mjs\`: реальный Chromium desktop/mobile на **синтетической** странице \`psk.testgifts.local\`, same-origin PDF MANUAL, SVG 0.12mm, растровый MLP, отсутствие внешнего fetch, экспертная метка, локальный JSON и очистка таблицы после закрытия.

## Как пользоваться в локальной сети

1. На ПК, открывающем тестовую таблицу, перейдите на https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-orders.html
2. Перетащите «Vision Check — заказы» в закладки либо скопируйте код закладки.
3. Откройте http://psk.testgifts.local/devorders?status=140 и авторизуйтесь при необходимости.
4. Нажмите закладку; убедитесь, что появился блок Vision Check и дополнительные ячейки в каждой найденной строке.
5. Нажмите «Проверить макеты». Для каждого доступного same-origin вложения появится исследовательский результат или MANUAL.
6. При необходимости поставьте экспертные метки и скачайте локальный JSON. Для уточнения структуры неизвестной таблицы нажмите «Диагностика таблицы» и передайте только этот структурный файл.

**Важный технический нюанс:** публичный HTTPS скрипт выполняется в контексте авторизованной локальной страницы и поэтому требует явного согласия пользователя. Он **не читает cookies**, но same-origin GET автоматически использует текущую сессию, как обычные ссылки на странице. В коде **нет** POST, телеметрии, localStorage, отправки внешним доменам или фонового обучения. На реальном сайте CSP может запретить выполнение скриптов с \`tohaa28.github.io\` — в таком случае требуется локальная копия исполняемого файла или расширение браузера, а не обход CSP. Ответные same-origin редиректы запрещены; перекрёстные ссылки на \`testgifts.local\` или другую поддоменную загрузку **не скачиваются автоматически**. Для них сначала согласовать реальные endpoints/CORS или безопасный same-origin proxy.

## Что НЕ доказано

- Структура реальной таблицы и точные URL вложений неизвестны. DOM-поиск адаптирован к стандартным \`table tr\` и \`[data-order-id]\`. Реальный контент может быть SPA, динамические кнопки, вложенные документы, файлы на другом поддомене, обязательный XSRF token или отдельная авторизация; нельзя заявить об успехе в LAN до фактического запуска.
- PDF исходные графические операторы и исходное ICC/spot остаются важнейшей P1 задачей; использовать PDF.js raster preview вместо исходных печатных форм нельзя.
- Текущий JSON с экспертными метками — это **исследовательские метаданные**, не полноценный обучающий датасет: он не содержит ни самих макетов, ни доказанной авторизованной привязки заказ→артикул→поле, ни подписанных ROI. Реальное обучение потребует безопасного локального хранилища и двух независимых технологов для разметки дефектных объектов.
- Отсутствие кандидатов никогда не означает «OK», все результаты \`production_approved:false\`. Никакой автоотправки заключений в заказы, изменения статуса 140 или записи результатов на локальный сервер нет.

## Следующие задачи O2 / P1

1. На локальном ПК пройти первичную диагностику таблицы и закрепить реальные DOM/selectors, способ получения вложений и пагинацию без раскрытия приватных URL. Сохранять page-side обработку и видимость результатов в каждой строке.
2. Реализовать **локальный контейнер обучающих данных** (отдельный настраиваемый local service, не публичный GitHub) и согласованный формат raw/vector samples, SHA-256, source hash, anonymized order key, expert ROI labels и family-level train/test split. Нельзя обучать автоматически на строковых метках без точной ROI-разметки и отделения верифицированных негативных примеров.
3. Приоритезировать векторные PDF/AI/EPS/CDR через отдельные безопасные парсеры/конвертеры и истинные печатные размеры.
4. После реальной проверки таблицы добавить локальную постоянную запись результатов в **тестовую** БД заказов с отдельными правами/endpoint и аудитом изменений. На этом этапе код не записывает ничего на сервер.

## Политика публикации

CI тестирует только синтетическую LAN-фикстуру; GitHub Pages обновляется **исключительно** в \`main/gifts-layout-workbench-vision/\`. В публичном GitHub — только исходники, инструкции и синтетические тесты; никаких тестовых заказов или оригинальных макетов.
