# Vision AI: из согласований макетов в проверяемый обучающий корпус

**Эксперимент, только тестовая сеть и локальный приватный ПК.** Исходные тексты и вложения заказчиков **не** помещать в GitHub, Issues, Actions, Pages, общедоступные чаты или внешнее хранилище. Ни одна запись не является достоверной обучающей меткой без подтверждения макета и экспертного ROI.

## Этап 1. Автоматический сбор из списка заказов

1. Установить или обновить Chrome MV3 Vision Check (не ниже v0.1.7): `https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-lan-extension.zip`.
2. В авторизованном Chrome открыть `http://psk.testgifts.local/devorders` (нужная выборка заказов).
3. Нажать **«Собрать согласования из всех заказов»** и разрешить Chrome множественные локальные скачивания.
4. Расширение последовательно переходит по каждому заказу во временной вкладке, открывает **штатное** «Согласование макета» для артикула с цифровым счётчиком **более 1**, считывает текущие отмеченные дизайнером проблемы, всю историю пользовательских сообщений и системных событий, галереи скриншотов и штатные файловые вложения. Скачать оригинальные байты пытается только разрешёнными GET, не меняя заказ.
5. В папке загрузок появляются резервный `vision-private-approval-evidence-<номер>-raw.json`, итоговый `vision-private-approval-evidence-<номер>.json` и ZIP-части вложений. Итоговый JSON сохраняет `order_facts`, **исходные имена участников**, все сообщения, текущие и исторические проблемы, время, ID и SHA-256 связей с файлами. Chrome подтверждает полное сохранение JSON перед закрытием вкладки.
6. **«Отчёт согласований JSON»** создаёт отдельно анонимные статусы и счётчики для диагностики. Не путать с более старой кнопкой «Найти обсуждения»: она не собирает тексты.

Факт наличия картинки/вложения в HTML **не** означает успешную загрузку её байтов. При 403/404, редиректе на авторизацию, неизвестном типе, превышении лимита или отсутствии бинарного содержимого сохраняется `MANUAL_*`, а не выдуманный «полученный файл».

## Этап 2. Приватное объединение и проверки

В корне локальной копии репозитория:

```powershell
python tools/vision_approval_training_corpus.py `
  --input-dir "D:\VisionPrivate\Downloads" `
  --output "D:\VisionPrivate\Corpus-001"
```

Также допустим повторяемый ввод `--evidence <json>` и `--archive <zip>` вместо `--input-dir`. Папка вывода должна **отсутствовать** до запуска. Не выбирайте каталог проекта/публичного репозитория.

При импорте проверяются исходные имена архивных частей, порядок, schema, принадлежность заказу, связи `артикул → сообщение → вложение`, содержимое ZIP и SHA-256 каждого файла. Ошибка, противоречие или дублирующийся ключ JSON означают отказ; никаких «угаданных» файлов. Архивы и исходные JSON сохраняются без изменений в `raw/`; проверенные оригиналы — в `assets/` с SHA-256 в имени. В Linux/macOS папка и файлы создаются с приватными режимами (0700/0600); на Windows права NTFS/ACL необходимо проверить отдельно.

Система строит следующие приватные таблицы JSONL:

| Файл | Назначение |
| --- | --- |
| `orders.jsonl` | Номер/внутренний ID заказа, дата, клиент, статусы, SHA-256 источника |
| `articles.jsonl` | Артикул, название, количество/цены, нанесения, техтребования |
| `messages.jsonl` | Сообщения/события, даты, исходные ID, **полные имена авторов** и псевдонимы |
| `problems.jsonl` | Только текущие отмеченные проблемы; исходный код, текст, технология и поле |
| `assets.jsonl` | Вложения, исходные имена и ID, SHA-256, путь к байтам или причина отсутствия |
| `relations.jsonl` | Ориентированные связи всех сущностей и порядок сообщений |
| `cases.jsonl` | Один кандидат на артикул с ссылками на связанные записи, блокерами подготовки |
| `review_queue.jsonl` | Очередь для ручного подтверждения связи с реальным дефектом |
| `manifest.json` | Контрольные счётчики, статус приватности и неподготовленности к обучению |

**Все поля связи сохраняются внутри приватного корпуса.** Названия, номера и тексты не появляются в системном stdout и логах CI. Синтетические тесты проверяют точное совпадение SHA, восстановление исходного файла и отсутствие автоматической выдачи подтверждённой метки.

## Этап 3. Формирование проверенного обучающего примера

Пока необходимы четыре независимые проверки:

1. **Идентичность исходного макета**: конкретный PDF/PSD и его ревизия, SHA-256 и связь с моментом замечания дизайнера. Текущий файл заказа может быть уже исправлен; одна переписка не доказывает предыдущую версию.
2. **Контекст нанесения**: артикул/поле, метод нанесения, физический размер, единицы, применимые технические требования.
3. **Геометрия дефекта**: ROI (bounding box, маска, сегмент векторной кривой, координаты на конкретном изображении). Снимок экрана может быть иллюстрацией, а не исходным макетом.
4. **Экспертная оценка**: две независимые проверки, при разногласии — аджудикация; отрицательные/исправленные примеры, проверки семейной дедупликации и отдельный holdout.

Для этих шагов уже существуют модули `vision/dataset/review-task.mjs`, `vision/dataset/prepare-blind-control-task.mjs` и `tools/vision_private_corpus_stage.py`. Новый импортёр **не обходит** их защиту и не передаёт данные автоматически на обучение. Текущие жалобы дизайнера, названия изображений, чекбоксы и эвристические темы имеют только статус *candidate evidence*.

`training_ready=false`, `production_approved=false` и `remote_upload=false` остаются обязательными. Проверка синтетических тестов: `python -m unittest discover -s tests -p 'test_vision_approval_training_corpus.py' -v`.

## Сохранённая HTML-страница без скачанных байтов

HTML-экспорт с видимой перепиской может позволить получить тексты сообщений, даты, ссылочные имена файлов и URL оригиналов в галерее. Но автономный HTML **не содержит бинарные PNG/JPG**; без авторизованного сбора в Chrome эти вложения должны оставаться `NOT_ATTEMPTED` или `MANUAL`. Не считать их проверенными и не заменять скриншот превью или HTML-фрагментом.

## Статус

- Расширение умеет читать обсуждения из списка заказов; реальная сессия тестового сайта по-прежнему требует проверки на машине пользователя.
- Конвертер локально переносит исходные тексты, системные события, вложения, комментарии и причинно-временные связи в кандидаты на обучение.
- Публичный репозиторий содержит **только код, документацию и искусственные тестовые фикстуры**, никаких данных реальных заказов.
- Это **конвейер подготовки и проверки**, а не обучение нейросети и не автоматическое признание дефектов.


## v0.1.7 — оригинальные авторы и расширенные сведения о заказе

Фоновая очередь автоматически сохраняет два JSON для каждого обработанного
заказа: `vision-private-approval-evidence-NNN-raw.json` (резервный,
до GET вложений) и `vision-private-approval-evidence-NNN.json`
(итоговый, с SHA-256 и ZIP-связями). В обоих присутствуют
`order_facts` (номер, внутренний ID, дата, сведения клиента,
статусы заказа, товары, артикулы, цены/количества текстом,
сведения о нанесении, требования и ссылки на карточки продуктов),
`current_problems`, `history` со всеми сообщениями и событиями,
`author_name`, `author_display_text`, `native_comment_id` и
`actor_ref`. Имена **не маскируются** в локальном корпусе. Выгрузка
не публикуется автоматически.

При импорте каталога `--input-dir` конвертер пропускает резервные
`-raw.json`, чтобы исключить дубликаты заказов, и использует итоговые
файлы. В `orders.jsonl` дополнительно попадают клиент/дата/статусы,
в `articles.jsonl` — код и название артикула, количество/цены
и технические требования, в `messages.jsonl` — оригинальные
имена и сообщения. Отдельные ZIP сохраняют исходные байты и SHA-256.
Расширению нужны права Chrome `downloads`; успех записи JSON
подтверждается после `state=complete`. Если итоговый JSON не сохранён,
перепроверить состояние Chrome по анонимному отчёту списка и взять
резервный вручную; не пытаться обучать на неполных данных.


## v0.1.8 — единый архив по всем заказам

Основная кнопка на \`devorders\` теперь:
**«Собрать согласования из всех заказов (один ZIP)»**. Она не инициирует
сотни отдельных скачиваний из временных вкладок. Страница списка
последовательно принимает ограниченные порции исходных сообщений
и изображений из каждого посещённого заказа; в конце формирует
**один** \`vision-ai-approvals-<дата>.zip\`. Для повторной попытки
доступна кнопка **«Скачать единый архив ZIP»**. При ручной остановке
можно сохранить частичную выборку или продолжить. До завершения
скачивания страницу списка не закрывать и не обновлять.

В корне ZIP — \`manifest.json\`, \`index/orders.json\`; для каждого
\`orders/<номер>/\` отдельные \`order.json\`, \`articles.json\`,
\`approvals.json\`, \`threads/<item_id>.json\`, \`files-index.json\`,
\`assets/<sha256>.<расширение>\`, \`review.json\`,
\`source/evidence.json\` и резервный \`source/backup.json\`.
Связь имён файлов с автором, временем, заказом, артикулом и сообщением
проходит через \`files-index.json\`. Старый формат отдельных выгрузок
поддерживается архивным импортёром, но больше не используется очередью
списка заказов v0.1.8.

Оффлайн импорт одного ZIP:
\`\`\`powershell
python tools/vision_approval_batch_import.py --batch-zip "D:\VisionPrivate\vision-ai-approvals-2026.zip" --output "D:\VisionPrivate\Corpus-001"
\`\`\`
Импортёр проверяет контракт ZIP32 STORED, допустимые пути, CRC,
SHA-256 оригиналов, связи \`сообщение → вложение\` и переводит
исходные файлы в прежний типизированный Vision JSONL корпус.
При несовпадении контрольной суммы — отказ без выдачи готовой метки.
Лимит браузерного пакета 180 МБ. Для большего набора используйте
несколько завершённых запусков, вместо игнорирования лимита.


## v0.1.9 — массовый отбор только утверждённых ТЗ

В панели Chrome на \`psk.testgifts.local/devorders\` есть отдельный
режим **«Диапазон заказов · статус „ТЗ утверждено“»**.
По умолчанию сканирование номеров 3 200 000–8 200 000,
включительно, **только после ручного старта**. Проверка происходит
последовательными GET с задержкой не меньше 1 секунды. Проверяется
не текст «ТЗ утверждено» (он может отображаться при выключенном статусе),
а исходный флажок с идентификатором 59 внутри \`#j_cart_host .cart-log\`,
его \`checked=true\` и точное совпадение номера заказа. Любая
неоднозначность статуса/авторизации останавливает обработку и
не объявляется «пропуском».

Только найденный заказ с включённым флажком открывается
во временной вкладке для штатного согласования. Статус
перепроверяется непосредственно перед чтением сообщений.
Каждые 100 **утверждённых** заказов создаётся отдельный
\`vision-ai-range-<от>-<до>-part-00001-<первый>-<последний>.zip\`
в том же формате \`printcheck.vision.local-batch-corpus.v1\`,
что использует уже созданный офлайн-импортёр
\`tools/vision_approval_batch_import.py\`. Партия может закрыться
раньше 100 заказов из-за лимита байтов, остановки или окончания диапазона.
Исходные изображения/тексты не теряют связи с заказом, артикулом,
исходным автором и сообщением.

После завершённого скачивания каждой ZIP-партии Chrome Downloads
подтверждает \`state=complete\`, и контрольная точка
\`chrome.storage.local\` запоминает следующую позицию и
реестр утверждённых заказов. При прерывании несохранённые заказы
пересканируются с последней подтверждённой позиции; сообщения
и бинарные файлы в Chrome storage не складываются.
Открытая страница списка заказов необходима всё время.
\`vision-ai-approved-orders-register.json\` выгружается отдельной
кнопкой и содержит архивированные и ещё не архивированные найденные
заказы, но не содержит обучающих меток. Реальный массовый диапазон
пока не тестировался; browser CI применяет три синтетические карточки
(checked/unchecked/404) и проверяет итоговый ZIP и checkpoint.
