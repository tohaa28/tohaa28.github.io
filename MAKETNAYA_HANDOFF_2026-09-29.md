## 3. Сопоставление полей, уже работающее

Цепочка:
`страница заказа / drawTask -> applicationId -> popup selected template -> локальная позиция в PDF -> printN / PDF field`.

Для шаблонов, где текстовая подпись поля в PDF недоступна, есть режим `application-sequence`:
- число реальных мест должно совпадать с числом найденных полей;
- локальные индексы должны образовывать 1..N;
- существующие PDF labels не должны противоречить последовательности;
- поля связываются с местами по PDF order / local template index;
- UI показывает `место · метод`.

## 5. Новое условие: fallback по фигурам с прозрачностью 98%

Требование пользователя:
если обычный поиск поля не нашёл нужное поле/нужное количество полей, искать фигуры произвольной формы с заливкой, имеющей прозрачность 98%.

Интерпретация PDF:
- прозрачность 98% = непрозрачность заливки около 2%;
- non-stroking alpha `/ca ≈ 0.02`;
- допуск сейчас `±0.005`;
- используется именно fill opacity `ca`, НЕ stroke opacity `CA`.

Реализация добавлена только как fallback:
1. Сначала работает прежний основной поиск цветных/векторных полей.
2. Если обычных полей меньше ожидаемого количества — добавляются кандидаты из замкнутых paths с fill opacity около 0.02.
3. Если ожидаемое количество неизвестно — opacity fallback используется только когда обычный поиск не дал полей.
4. Дубликаты по геометрии удаляются.
5. Основной способ определения поля всегда имеет приоритет.

Поддерживаемая геометрия:
- rectangle;
- polygon;
- Bezier / произвольный path;
- bounding box поля берётся из PDF.js path bbox.

Metadata opacity-fallback поля:
- `source="pdf-opacity-98-fill"`
- `fillOpacity≈0.02`
- `transparency≈0.98`
- `shapeKind="arbitrary-path"`

PDF.js:
- ExtGState читается через `setGState`;
- отслеживаются save/restore и transforms/Form XObject;
- проверяется как отдельная paint operation, так и fill-op, встроенная прямо в `constructPath`.

После `8be06a...` изменения приложения не вносились: `402a...` — документация, `2236e...` — тестовый assert. Поэтому рабочий код fallback в опубликованной версии соответствует последней зелёной точке `8be06a...`.

При продолжении:
- НЕ откатывать приложение;
- либо адаптировать legacy mock 7920510 под реальную draw-task DOM-структуру,
- либо не требовать applicationBindings в тесте, который специально проверяет другой сценарий.
