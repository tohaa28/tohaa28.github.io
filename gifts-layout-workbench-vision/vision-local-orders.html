Vision Check · тестовые заказы

Изолированный экспериментальный модуль для таблицы http://psk.testgifts.local/devorders?status=140. Запускается поверх открытой страницы в локальной сети и добавляет результаты к строкам заказов.

Установка закладки запуска

  1. На компьютере, подключённом к тестовой локальной сети, откройте эту страницу установщика.
  2. Перетащите кнопку Vision Check — заказы на панель закладок (Ctrl + Shift + B).
  3. Откройте тестовую таблицу на psk.testgifts.local/devorders?status=140, при необходимости авторизуйтесь.
  4. Нажмите закладку. Vision добавит колонку в таблицу. Начните с кнопки «Проверить строку» для одного заказа. Кнопка «Проверить все заказы» читает все карточки и все найденные файлы последовательно, по одному, без общего лимита количества. «Остановить после файла» приостанавливает очередь; «Продолжить очередь» возобновляет её без повторного скачивания уже проверенного. Ограничение размера одного файла и проверка безопасных адресов сохранены.

Если карточки заказов блокируются: локальное расширение Chrome

На реальной таблице 17 ноября первые 10 запросов карточек завершились ошибкой, которую старый обработчик обозначал ORDER_DETAIL_FETCH_OR_CORS_FAILURE. Причина по прежнему JSON неразличима: серверный редирект, CORS, отключённая сеть или авторизация. Новый отчёт разделяет этап order_card и popup и указывает, совпадает ли разрешённый origin карточки с origin таблицы, не раскрывая адресов или номеров.

Скачать локальное расширение Chrome (ZIP) Инструкция и разрешения расширения

Установите только в тестовом профиле Chrome: распакуйте ZIP в постоянную папку, откройте chrome://extensions → «Режим разработчика» → «Загрузить распакованное расширение». Укажите папку, где лежит manifest.json. Разрешены только http://psk.testgifts.local/* и http://testgifts.local/*. На тестовой странице расширение появляется автоматически, старая закладка одновременно не нужна. Запросы выполняются через Chrome service worker с явным разрешением пользователя, а не через запрещённый браузером cross-origin fetch страницы.

Расширение не делает автоматические GET до нажатия «Проверить строку» / «Проверить следующие 10 заказов»; настоящую авторизацию и пригодность файлов для обучения ещё нужно проверить на вашем ПК.

Локальный тестовый стенд на диске D:

Подготовлен автономный стенд D:\VisionCheckLab: импорт подписанных экспертными метками тестовых ZIP, проверка SHA-256, приватное хранилище оригиналов, SQLite-реестр, журнал ROI и панель только на 127.0.0.1. Данные из локальной сети не отправляются в GitHub.

Скачать установщик стенда для D: (ZIP) Инструкция установки на D:

Распакуйте ZIP, затем запустите PowerShell из извлечённой папки: powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install-vision-local-lab.ps1. Python 3 с командой py -3 обязателен. Эта страница сама не может записывать файлы на диск D.

Новая локальная ROI-разметка и PDF-аудит

После переустановки лаборатории откройте D:\VisionCheckLab\OPEN-ROI-ANNOTATOR.cmd. Выберите исходный SVG/растровый файл, укажите sample-id и SHA-256 из команды list, выделите область и выполните полученную команду. Система не разрешит привязать выделение к другому файлу. Два независимых эксперта подтверждают или отклоняют ROI; расхождения рассматривает третий.

Для PDF в локальной лаборатории добавлен исследовательский аудит геометрии страниц и векторных путей — tools\vision_pdf_audit.py. Для него нужен отдельно установленный PyMuPDF с учётом AGPL/коммерческого лицензирования. Ни аудит, ни согласованные ROI пока не означают готовности макета к печати или допуска к обучению. Очередь vision_roi_review.py prioritize сортирует спорные и ещё неразмеченные случаи для экспертов.

Что сейчас проверяется

SVG по исходной векторной геометрии, PNG/JPEG/WebP как вспомогательное растровое исследование. PDF скачивается и распознаётся, но до полноценного разбора векторных операций, цветоделения и физического масштаба помечается MANUAL. CDR/AI/EPS/ZIP также требуют отдельного обработчика.

Можно поставить экспертную метку для каждой строки, скачать анонимный JSON-отчёт или все исходные тестовые файлы в локальных ZIP-частях. Для сохранения разрешена также метка «Не размечено»: такой файл не участвует в обучении. Нет общего лимита числа файлов; одна ZIP-часть ограничена 16 файлами и 24 МБ, один файл — 16 МБ. ZIP скачивается только после отдельного подтверждения; браузер может запросить разрешение на несколько загрузок. Файлы не загружаются в GitHub.

Каждая ZIP-часть содержит manifest.json и исходные тестовые вложения с оригинальными именами. Метка всей строки ещё не является разметкой конкретного дефектного объекта: для обучения нужны ROI, подтверждённый масштаб, хеши источников и независимая контрольная выборка. Не размещайте ZIP в публичных репозиториях.

Если таблица не распознана, кнопка «Диагностика таблицы» создаёт JSON только со счётчиками строк и ссылок, без заказных номеров, адресов вложений и исходных файлов. Его можно использовать для настройки адаптера.

Без передачи макетов на внешние серверы. Загруженный из таблицы файл обрабатывается внутри браузера на локальном origin; автоматических POST, телеметрии, загрузки на GitHub или сохранения исходных макетов в репозитории нет. Публично размещается только код. Исходные файлы и пользовательские идентификаторы в JSON отчёт не включены.

Доступность файлов проверяется через /private/order/<номер> → makets_popup → /cart/act/mda. Между psk.testgifts.local и testgifts.local браузер может требовать разрешённый CORS; неподдерживаемая авторизация приводит к MANUAL, а не обходится. Эталонные конструкторы /drawing не считаются клиентскими макетами.

Для работы необходим браузерный доступ к этой локальной сети. Если реальные ссылки используют другой поддомен или отличаются от тестовых HTML-селекторов, модуль не обходит CORS и не угадывает адреса — потребуется адаптер после осмотра структуры страницы. Политика Content Security Policy тестовой сети также может блокировать запуск внешнего скрипта; в таком случае понадобится локальная установка или расширение браузера.
