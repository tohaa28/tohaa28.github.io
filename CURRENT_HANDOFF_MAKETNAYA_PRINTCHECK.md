## 6. Новый выбранный математический подход

После исследования методов компьютерного зрения принято направление:

**control circle / local thickness / maximal inscribed circles**

Главная идея:
- минимально разрешённый размер = диаметр контрольного круга;
- для печатаемой фазы нужно понимать, где такой круг физически помещается внутри элемента;
- для negative gaps та же проверка проводится по непечатаемой фазе;
- ordinary border толстого объекта сам по себе не дефект;
- участок считается тонким не потому, что находится рядом с краем, а потому что локальная геометрия не допускает круг требуемого диаметра.

Используемые понятия:
- binary mask;
- distance transform;
- medial axis;
- morphological opening;
- local thickness;
- control-circle coverage;
- connected components только там, где они реально нужны.

## 7. Правила positive

Positive — печатаемый элемент.

Должно находиться:
- реальная тонкая линия;
- реальная тонкая перемычка;
- длинный/повторяющийся участок ниже допустимой толщины;
- маленький самостоятельный печатаемый объект.

Не должно находиться:
- обычный внешний край толстого объекта;
- круглый/прямой торец толстого штриха;
- короткий клиновидный сход;
- угол буквы;
- место, где элемент только визуально приближается к краю;
- граница другого печатного цвета.

Marker:
- один marker на осмысленный найденный участок;
- центр marker — внутри узкой зоны / по её оси;
- диаметр marker = минимально допустимый размер;
- без центральной точки;
- не делать цепочки кружков вдоль нормального контура.

## 8. Правила negative

Negative — непечатаемый пробел внутри/между участками одной печатной краски.

Должно находиться:
- узкий белый/непечатный канал внутри одного печатаемого цвета;
- узкий промежуток между отдельными участками того же печатного цвета;
- замкнутая узкая выворотка/отверстие.

Не должно находиться:
- внешний фон рядом с одним контуром;
- пространство между разными печатными цветами;
- пересечение разных цветов;
- антиалиасинговая переходная полоса.

Важно: прежнее правило «open channel внутри одного connected component всегда игнорировать» было отменено как слишком грубое. Реальный белый канал внутри синего рисунка может быть дефектом даже если синий геометрически остаётся одним connected object.

## 9. Цвета

Цвет нанесения заранее не фиксирован.

Пример пользователя — синий ink + белые gaps, но алгоритм должен работать для любого цвета.

Правила:
- анализировать реальные ink-фазы;
- разные ink colours проверять отдельно;
- не измерять толщину «между двумя разными цветами»;
- граница red↔blue и т.п. не является negative gap;
- SVG/PDF исходная palette может помогать отделить настоящие краски от антиалиасинга;
- PNG/JPG должны работать без vector metadata.

## 10. Raster / Vector parity

Обязательно поддерживать:
- SVG;
- PDF;
- PNG;
- JPG.

После rasterization/подготовки масок геометрический алгоритм должен быть единым.

Вектор может дать дополнительную информацию:
- исходные цвета;
- прозрачности;
- другие структурные данные.

Но корректность поиска мелких элементов не должна зависеть от наличия векторной структуры.

## 12. Отдельные объекты

Критическая ошибка старой версии: один рисунок дробился на тысячи объектов из-за цветовой сегментации/антиалиасинга.

Правильное правило:
- isolated object определяется по общей видимой геометрии рисунка;
- цветовые подслои одного непрерывного визуального объекта не должны становиться отдельными isolated objects;
- реально отделённый маленький фрагмент должен находиться;
- dense detached grid / много действительно раздельных объектов должно классифицироваться как отдельные объекты, а не как thin edge noise.

## Дополнение 2026-10-06 — PrintCheck v16 exact Euclidean opening

После v15 обнаружена конкретная причина двух регрессий первой попытки exact opening: после замены chamfer distance на Euclidean Distance Transform в dilation-части `circleOpening` сохранилось старое деление `/3`. В результате Euclidean-расстояние ошибочно масштабировалось как chamfer 3/4 и реконструкция контрольного круга получалась примерно втрое шире.

Исправлено:
- `circleOpening` теперь использует exact Euclidean Distance Transform и для поиска центров контрольного круга, и для восстановления covered-area без старого `/3`;
- final local thickness остаётся Euclidean;
- candidate-компоненты по-прежнему проходят фильтрацию углов/торцов, но `taperToOneBody` теперь оценивает профиль толщины вдоль медиальной оси;
- длинная равномерно тонкая ветвь, присоединённая к толстому объекту, больше не отбрасывается как taper;
- короткий клиновидный сход/угол по-прежнему не считается дефектом;
- исправлена JS-ошибка typed-array: `Int32Array.map(i => [distance,width])` заменён на `Array.from(...)`, иначе пары профиля превращались в нули.

## Дополнение 2026-10-06 — исправление физических размеров полей Макетной

После пользовательского замечания о завышенных размерах полей проверена вся цепочка `PDF points → mm → field geometry → order size → templateScale → nominalW/nominalH`.

Найдено две независимые проблемы:
- fallback-парсер текста PDF ранее считал любую запись `A × B` сантиметрами и всегда умножал оба числа на 10, даже если в PDF было явно написано `мм/mm`; это могло превратить правильное поле 32×32 мм в nominal 320×320 мм через scale-aware matching;
- CSS `#stage { max-height:100% }` мог сжимать только высоту высокой страницы, не меняя ширину, и визуально растягивать шаблон/поле.

Исправлено:
- размер из текста PDF принимается как size metadata только при явной единице `мм/mm/см/cm`;
- `мм/mm` остаётся без масштабирования;
- `см/cm` переводится в мм ×10;
- unitless `A × B` больше не влияет на автоматический physical scale;
- scale-aware конструкторы 1:10 сохранены: геометрия 3.2 мм + подпись `3.2 × 3.2 cm` корректно даёт nominal 32×32 мм;
- удалён `max-height:100%` у stage; при высокой странице сохраняются пропорции, а лишняя высота прокручивается штатным `stageScroll`.

Контрольные результаты browser regression:
- артикул 15637 из order popup: лицо 32×32 мм, оборот 32×32 мм;
- synthetic explicit `32 × 32 mm`: UI = 32.00 × 32.00 мм, не 320×320;

## Дополнение 2026-10-07 — PrintCheck v19: двухсторонняя медиальная ось и ускорение EDT

По пользовательскому скриншоту одноцветного синего растрового рисунка при LM1 обнаружен характерный дефект v18: сотни жёлтых/голубых маркеров располагались цепочками вдоль обычных границ рисунка, а минимальные размеры часто были около одного пикселя (~0,02 мм в показанном прогоне). Одновременно анализ заметно замедлился.

Корневая причина false positive:
- старый `medialAxis()` принимал пиксель за осевой, если distance transform уменьшался хотя бы с одной стороны;
- на ступенчатой/кривой растровой границе это позволяло обычному краевому пикселю с радиусом 1 px попасть в «ось» и получить ложную локальную толщину 1 px;
- для negative та же ошибка могла принимать пиксели у стенки широкого белого канала за центр узкого пробела.

Исправлено в `PrintCheck-control-circle-v19-two-sided-medial`:
- осевая точка принимается только если distance transform убывает до границы в двух противоположных направлениях;
- проверяются 8 ориентаций, включая промежуточные 2:1 / 1:2, чтобы сохранять диагональные тонкие перемычки;
- поиск оси ограничен только диапазоном толщин, релевантным текущему контрольному кругу;
- широкая щель между двумя стенками больше не получает маркеры на своих краях;
- растрированная толстая кривая не создаёт однопиксельные positive-маркеры;
- короткие taper/corner convergence по-прежнему исключаются: добавлен анализ профиля ширины missing-компонента по расстоянию от основной формы;
- длинный равномерный тонкий spur и тонкий zigzag по-прежнему считаются настоящими дефектами.

Ускорение:
- ранее `oneBodyTaper()` запускал полный Euclidean distance transform заново для каждого missing-компонента;
- теперь EDT до opened-области вычисляется лениво максимум один раз на слой и переиспользуется;
- для single-ink не строится и не EDT-анализируется пустая маска «других красок»;
- устранён лишний полный проход `centers.some(Boolean)`;
- worker cache наконец поднят отдельно: `logo-detail-worker.mjs?v=20261007-1`, поэтому браузер больше не может продолжать исполнять старую закэшированную worker-версию.

Добавлены regressions:
- wide open channel > negative threshold при обеих стенках в радиусе поиска -> 0 false positives;
- rasterized curved stroke > positive threshold -> 0 one-pixel edge markers;
- true thin straight/diagonal/zigzag/spur сохраняются;
- short corner convergence сохраняется как допустимый;
- все предыдущие raster/vector, single-ink, antialias, colour-boundary, isolated, open-channel и browser regressions сохранены.
