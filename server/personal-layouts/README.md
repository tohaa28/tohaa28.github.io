# Серверная библиотека личных макетов «Макетной»

**Статус:** код клиентского API и изолированного серверного хранения реализован; **сервер на gifts.ru не подключён**. GitHub Pages не умеет исполнять Node/API, а доступ к существующему Vercel-проекту через доступное подключение возвращает HTTP 403. Без проверки сеанса на самом сервере публикация клиентских макетов запрещена. Публичный GitHub-репозиторий не используется для их хранения.


## Формат сохранённых макетов (18.10.2026)
При новом сохранении клиент использует штатный конструктор PDF `gwbCreateReadyLayoutPdf()`. На приватном сервере должны храниться **два** независимых файла: `<id>.pdf` — печатный вариант с конструктором и размещёнными логотипами, `<id>.json` — исходные файлы логотипов, размеры и координаты для ручного восстановления в редакторе. Старые записи без PDF могут быть восстановлены, но для получения PDF их необходимо сохранить заново.

В `POST /v1/layouts?article=...` дополнительно передаются `pdf` (base64 бинарного PDF) и `pdfName`. Сервер проверяет `%PDF-`, ограничения размера, записывает `.pdf` в приватное долговечное хранилище и возвращает `hasPdf:true`. `GET /v1/layouts/:id/pdf?article=...` отдаёт `Content-Type: application/pdf` **только авторизованному владельцу**. `DELETE` удаляет оба файла.

В пользовательском интерфейсе библиотека оформлена **отдельным блоком** и содержит кнопку `Скачать PDF`. Кнопка `Импортировать копию` и видимый импорт JSON удалены; скрытых автоподстановок личных макетов в заказы нет. Если сервер не подключён к gifts.ru, PDF и редактируемый исходник сохраняются лишь в IndexedDB браузера с явным предупреждением — не считать их серверной копией.

## Подключение к gifts.ru
1. На стороне **доверенного gifts.ru веб-шлюза**, имеющего доступ к серверному состоянию сессии, добавить маршрут `https://gifts.ru/private/maketnaya-layouts/v1/*`, проксирующий в этот Node API, заменяя публичный prefix `/private/maketnaya-layouts` на пустую строку (так `/v1/me` проксируется как `/v1/me`).
2. Веб-шлюз должен проверить реальную cookie-сессию gifts.ru. При отсутствии/истечении — HTTP 401, не передавать запрос далее. После проверки прочитать **внутренний неизменяемый ID** и отображаемое имя пользователя, назначенное gifts.ru. Нельзя доверять имени, ID, cookie или заголовкам, пришедшим от клиентского JavaScript.
3. Удалить любые присланные браузером `X-Gifts-User-*` и `X-Gifts-Identity-*`. Создать новые доверенные заголовки:
    - `X-Gifts-User-Id: <стабильный внутренний ID из серверной сессии>`
    - `X-Gifts-User-Name-B64: <UTF-8 имя в кодировке base64url, без padding>`
    - `X-Gifts-Identity-Time: <Date.now() в миллисекундах>`
    - `X-Gifts-Identity-Signature: <hex(HMAC_SHA256(SECRET, ID+"\\n"+BASE64URL_NAME+"\\n"+TIMESTAMP))>`
   Секрет HMAC существует только у gifts.ru шлюза и у Node API, 32+ символа. Для безопасности в API сравнение происходит в постоянное время, срок годности подписи ±60 секунд.
4. Node API доступен только шлюзу, не напрямую из интернета; конфигурация окружения `GIFTS_IDENTITY_HMAC_KEY` (обязательно), `GWB_PRIVATE_LAYOUT_ROOT` (путь с доступом только серверному пользователю, **за пределами публичного сайта**), `GWB_LAYOUTS_PORT` (по умолчанию 8787), `GWB_LAYOUTS_BIND` (по умолчанию `127.0.0.1`). Команда: `node server/personal-layouts/index.mjs` (Node >=22). Для постоянного хранения необходимо подключить приватный долговечный диск/том; ephemeral filesystem серверлесс-функции не подходит.
5. Проверить запрос `GET /private/maketnaya-layouts/v1/me` из авторизованного сеанса и убедиться, что сервер отвечает `{authenticated:true,id:"...",name:"..."}`; при отсутствии авторизации ответ должен быть 401. Модель фронтенда отвергает несоответствие этого имени тому, что показано в личном меню gifts.ru.
6. Проверить POST/GET/DELETE под двумя настоящими пользователями. Пользователь B не должен видеть и удалять макеты A; каталог сохраняется строго по внутреннему ID, а не по совпадению ФИО или любому номеру заказа. POST и DELETE требуют `Origin: https://gifts.ru`; CORS не открывается.

## API
- `GET /v1/me`: подтверждение сервера.
- `GET /v1/layouts?article=15637`: метаданные записей текущего авторизованного владельца и артикула.
- `POST /v1/layouts?article=15637`: новый `personal-draft` с исходными файлами логотипов, геометрией всех полей, миниатюрой и названием.
- `GET /v1/layouts/:id?article=15637`: сам сохранённый вариант, включая исходные логотипы в base64.
- `GET /v1/layouts/:id/pdf?article=15637`: скачивание реального PDF-файла, доступное только владельцу.
- `DELETE /v1/layouts/:id?article=15637`: удаление JSON и PDF, недоступное чужому пользователю.

Ни один API не привязывает личный вариант к номеру заказа или не запускает печать. Восстановление всегда выполняется только по явной команде пользователя и с проверкой геометрии конструктора.

## Безопасный режим без сервера
После открытия «Макетной» проверяется `/private/maketnaya-layouts/v1/me`. Если он отсутствует, интерфейс явно показывает **«Сервер недоступен · локальный резерв»** и кнопку **«Сохранить локальную копию»**. Пользователь никогда не получает ложного сообщения о якобы успешной серверной записи. Действующие локальные варианты остаются доступны на этом устройстве и могут быть выгружены в JSON.

## Проверки
- `tests/personal-layout-private-server.test.mjs`: запускает настоящий локальный Node-сервер и проверяет HMAC, русские имена, изоляцию артикулов и владельцев, подделку подписи и отказ в межсайтовой записи.
- `tests/personal-layout-server-browser.mjs`: проверяет автоматическое подключение к подписанному серверному контракту, сохранение, список и восстановление только по кнопке в реальном Chromium.
- `tests/personal-layout-library-browser.mjs`: дополнительно проверяет локальный резерв, импорт/экспорт и то, что без реального сервера нельзя заявлять о серверной записи.

**Для включения production требуется доступ к gifts.ru reverse proxy и доверенному внутреннему механизму проверки авторизации.** Существующее подключение Vercel не имеет разрешения на чтение/изменение проекта (HTTP 403). Не заменяйте этот барьер передачей логина или пароля gifts.ru на сторонний сервер.
