# Макетная: сводная история разработки и решений (сентябрь — 21 октября 2026)

> Эта история охватывает основные этапы и решения; **первичные подробные журналы handoff/** являются обязательным дополнением и включены в архив исходной ветки. Нельзя выкидывать оригинальные исторические файлы из репозитория. Неподтверждённые личные данные заказов не публиковать.

## Сентябрь: основание архитектуры и технические требования

- Цель: по заказу gifts.ru получать реальные артикулы, выбранные нанесения и конструкторы; переносить оригинальные логотипы в поля, анализировать техническую пригодность, выдавать готовые PDF. Поддерживать Windows/Android PrintCheck как отдельное направление, но Макетная — веб-клиент.
- Отказ от синтетического обнаружения полей: реальные поля [print1], [print2] и контуры из шаблона; сопоставление конструкторов артикулу, исключение служебной таблицы.
- PrintCheck: положительные линии, островки и мостики, отрицательные просветы/выворотка, минимальные физические диаметры, охранное поле, виды печати, цвета, текст без кривых, растры, градиенты и прозрачности. Пороговые значения зависят от нанесения.
- Архитектура GitHub Pages + bookmarklet внутри gifts.ru. Изначальная цель — приоритет надёжной технической обработки, а не генерации декоративных превью.

## 1–8 октября: мелкие детали PrintCheck и инфраструктура

- Ранний PrintCheck ловил ложные края, пропускал тонкие линии и путал разные цвета; алгоритм менялся для симуляции проверки кружком минимального разрешённого диаметра, с позитивными и негативными проходами, цветовой сегментацией и обнаружением отдельных компонентов.
- Вводятся собственный raster/vector анализ, worker, overlay меток на поле, статусы «поиск мелких элементов…», кеши и ограничения производительности. Разные релизы V24/V25; реальная полнота детекции остаётся QA задачей.
- Размер поля (а не всего PDF) показывать в режиме поля; размер страницы — при просмотре конструктора целиком.

## 3–14 октября: пошаговая Макетная, интерфейс, мокапы

- Авторизация сайта gifts.ru; корзина обновляется заново при запуске; заказ читается с реальными артикулами/кодовыми местами печати. Начало: список заказов, затем артикул, место, конструктор.
- Список корзин/заказов в компактных карточках с группировкой, раскрытием многопозиционных заказов, числом позиций, датой, фото и верными названиями нанесений; для одного артикула — автоматический выбор артикула, но исходно показывается полный шаблон.
- Анимация входа как открытие дверей; движение персонажа, современный простой интерфейс с доступом к углублённым настройкам. Единый gifts.ru стиль. Переход в мокапы с надписью «Визуализируй это».
- Редактор мокапов: загрузка фотографий изделия из gifts.ru, привязка фото ↔ поле, несколько мокапов для одного места, серверное хранение разрешённых общих настроек, без появления белого/иного искусственного фона.
- Цилиндрические изделия: размещение поля на поверхности, сохранение proportions, реальные дуговые координаты, perspective/warp, отсечение невидимой обратной стороны, логотип по развёртке относительно ручки. Фиксированы вертикальные искажения и смещения.

## 14–16 октября: данные нанесений, цветность и вектор

- Настройки технологии автоматически выбираются для текущего заказа и сохраняются на сервере для всех пользователей; source of truth — method-settings.json.
- Разделение: когда в заказе перечислены печатные краски, для некоторых способов обязателен вектор; если краски не указаны, растровый исходник не объявлять дефектом без независимых причин.
- Сопоставление числа красок с конкретным заказом, Pantone/CMYK/RGB, белой подложкой, TT по выбранной технологии.
- Добавлен «Редактор логотипа»: VectorCraft как встраиваемый WASM, передача исходного логотипа и field mm, редактирование и возврат без фона/страницы/конструктора; не разрешать свободное создание другого документа. Сначала пилот интеграции, потом полноэкранный Gifts theme и перенос результата единственной кнопкой.

## 17–19 октября: VectorCraft, собственная библиотека и TraceDraw

- VectorCraft полноэкранный, закрытие Макетной скрывается при открытом редакторе, цветовой режим рабочего документа CMYK. Сохранённые пользовательские PDF-макеты по пользователю/артикулу — важное требование, но реальная доверенная серверная авторизация для личной библиотеки ещё требует подтверждения (документ: MAKETNAYA_PDF_LIBRARY_SEPARATE_2026-10-18.md).
- Undo/Redo в поле, drag/drop из Проводника, инструментами редактирования управлять из активного поля. Старый стек редактора должен быть доступен в нужном режиме, новые кнопки не должны ломать нативный canvas.
- TraceDraw на Rust/WASM с собственным мостом: наряду с VectorCraft второй редактор логотипа. Выбор в стиле Gifts, анимация между редакторами, передачa текущего поля/логотипа и возврат точных границ без artboard. Direct CDR import ещё не закрыт, не заявлять его наличие.
- CMYK-PDF roundtrip сохраняет реальные PDF color operators и физические размеры, векторная геометрия не подменяется SVG-скриншотом.

## 20 октября: реальные файлы в gifts.ru и готовые макеты

- Подтверждён пример заказа 8006776 в переданном пользователем HTML: два PDF из «Макеты для заказа» → «Загрузка макетов». Работа только с собственно загруженными клиентскими файлами; не использовать «Согласование макетов». Нельзя автоматически приписывать один из PDF выбранному item или полю без доказательства.
- Появились списки загруженных PDF, загрузка/скачивание/удаление по индивидуальному ID, кнопка открытия для редактирования, доступ после обновления корзины. Импорт стороннего PDF производится через VectorCraft/TraceDraw, не автоматически в поле конструктора.
- Вводятся безопасные загрузки готового PDF обратно в заказ; удаление только конкретного файла, не все макеты заказа. Переписывание gifts.ru клиентских файлов без согласия пользователя запрещено. Переходы и прогресс.
- Релиз drag/drop логотипа из Проводника в выбранное поле подтверждён ранее пользователем; старый утверждённый checkpoint **r6a2d4657** (см. START_NEW_CHAT_MAKETNAYA_2026-10-20.md).

## 21 октября: PDF-provenance, безопасность редакторов и сохранение

- PDF, экспортированный Макетной, теперь несёт переносимый бинарный GZIP manifest + самостоятельные PDF исходных логотипов, SHA-256, order/article/field/page/placement; иконка «М» в списке макетов. Это распознавание, не криптографическая подпись/шифрование. Старый незнакомый PDF нельзя автоматически разделить на шаблон/лого.
- Когда выбирается конструктор, все инструменты логотипа недоступны; после входа в поле доступны. Фикс stale aria-disabled у crop tool и повторная нативная синхронизация.
- Возврат VectorCraft/TraceDraw снабжён стадийным процентом и модальной блокировкой. При частичном сбое старый файл не заменяется.
- «Сохранить макет в заказ на gifts.ru» / «Сохранить как.. макет в заказ на gifts.ru»: Save для конкретного открытого PDF (новая upload-версия → серверная проверка → удаление одного старого ID), Save As создаёт новый PDF; нет атомарного endpoint, частичная операция сохраняет обе копии и сообщает о проблеме. Вся логика дублируется в простой/расширенной ветках интерфейса.
- TraceDraw исправлен для растров: поддерживаемые JPEG/WebP в embedded SVG приводятся к PNG, исходные позиции и пропорции сохраняются. Для возврата RGB/CMYK разрешены смешанные PDF без насильственного окрашивания; Rust guard не даёт выдать PDF без bitmap, если в SVG присутствовал bitmap.
- PrintCheck после возврата редактора: Qe(file,"art") заново разбирает PDF, inspectArtwork работает с НОВЫМ объектом, pe()/checkLogo() и детальный скан получают новый кеш-ключ. Старые дефекты должны исчезать только при фактическом изменении графики. Релиз r94ee2eae, CI 39601700251.
- **Последний функциональный релиз r7fa6f062**: устранены (а) простая замена color_mode на CMYK вместо фактического конвертирования объектов в VectorCraft — нативная команда file.documentColorMode + convert=true; (б) ложные RGB-false-positives у PrintCheck от неиспользуемых rg/RG и неиспользуемых PDF XObject. Сохранён анализ реально отрисованных операторов и RGB внутри использованного растра. CI 39607112412 SUCCESS; живой VectorCraft WASM 39606367485 SUCCESS. Отчёт: MAKETNAYA_VECTORCRAFT_COLOR_PDF_EVIDENCE_2026-10-21.md.
- **Открыто:** ручная проверка пользователем собственного проблемного файла и уточнение направления CMYK ↔ RGB; только после воспроизведения решать, требуется ли новая коррекция.
