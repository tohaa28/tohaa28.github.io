# Vision AI 0.2.0 — очередь TXT без /devorders и реестр ZIP
Дата: 2026-11-20. Ветка: `feature/printcheck-vision-copy-v01`.
PR #4 DRAFT: не сливать в production.

## Запрос
- Сканирование только по импортированным 7-значным номерам TXT.
- Работа с любой авторизованной страницы `http://psk.testgifts.local/*`
  или `http://testgifts.local/*` без открытия /devorders.
- Настройка места сохранения ZIP; список фактически сохранённых архивов.
- Устранить конфликт версий при обновлении и блокировку повторного запуска.

## Реализация
1. Из manifest MV3 удалён скрипт таблицы `vision-order-overlay.js`.
   В новой поставке нет режима диапазона; есть только launcher для двух
   тестовых порталов и штатный reader для /private/order/.
2. `scanner-host.html` + `scanner-host.js` запускают контроллер
   `approval-file-controller.mjs` в отдельном chrome-extension:// origin.
   Background worker открывает одну неактивную вкладку движка, а **не
   таблицу заказов**. IndexedDB очереди находится в origin расширения.
   Авторизованные GET выполняются прежним ограниченным потоковым портом
   только на разрешённые пути тестовой сети. Для согласований, требующих
   DOM, временно открывается соответствующая неактивная карточка заказа.
3. `archive-registry.js` ведёт IndexedDB-реестр скачиваний по download ID,
   оригинальному имени, размеру и последующему Chrome state. Статус
   `saved` выдаётся только после `downloads.state=complete`,
   совпадения размера, допустимого security verdict и наличия файла.
   Во время сохранения ZIP очередь может продолжать работу.
4. Настройки `chrome.storage.local`:
   - `downloads`: подкаталог `VisionAI` (или выбранное название)
     внутри стандартной папки «Загрузки» Chrome. Фоновая очередь
     автоматически сохраняет каждый ZIP без запроса.
   - `ask`: системный диалог «Сохранить как» для **каждого** ZIP;
     пользователь может указать произвольное место на диске.
     Chrome не позволяет расширению задавать постоянный произвольный
     абсолютный путь через downloads API без участия пользователя.
5. Панель на каждом тестовом портале: TXT импорт, запуск, пауза, стоп,
   ZIP, реестр заказов, сброс, проверка сохранения, выбор режима папки,
   список и JSON экспорт архива, ручной перезапуск зависшего движка.
6. При обновлении автоматически удаляется устаревший ключ диапазонного
   сканера из `chrome.storage.local`. Старая таблица больше не
   используется и старый runtime UI не устанавливается. **Старые
   IndexedDB, созданные в origin testgifts/psk.testgifts, не удаляются
   автоматически**: они могут содержать ещё не архивированные исходные
   файлы. Чтобы избежать потери материалов, сначала сохранить/проверить
   предыдущие ZIP, затем при необходимости вручную очистить старое
   хранилище сайта. Очистка данных расширения уничтожит и новую очередь.

## Проверка
- `node --check` новых JS/MJS.
- `tests/printcheck-vision-scanner-host.browser.mjs` — синтетический
  Chromium: старт с /catalog, импорт TXT, 404, статус с двух доменов,
  одна extension-host вкладка, отсутствие /devorders, настройки ZIP,
  очистка прогресса и запрет панели на login.
- Обязательна проверка реальной авторизованной сессии и сохранения ZIP
  в обеих настройках; синтетический CI не подтверждает доступ к LAN.
- Старая ветка и PR remain isolated; основная «Макетная» не затронута.

## Установка
Скачать архив по постоянному адресу
https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-lan-extension.zip
после зелёной сборки публикации. Распаковать поверх **того же каталога**
установленного расширения, затем нажать «Обновить» на
`chrome://extensions`, перезагрузить страницы двух доменов.
Для сохранения прежней очереди v0.1.16 сначала экспортируйте её ZIP
и реестр: новый движок хранит очередь отдельно и начинает с пустого TXT.
