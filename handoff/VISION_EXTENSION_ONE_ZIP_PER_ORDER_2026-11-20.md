## Ошибка, причины и исправление
Сообщено, что v0.2.0 не сохраняет переписки при сканировании. Появился
новый сквозной Chromium-тест `tests/printcheck-vision-host-approvals.browser.mjs`:
синтетический авторизованный заказ, native checkbox 59, динамическое окно
«Согласование макета», два сообщения, отмеченная проблема дизайнера,
скриншот, передача пакетами через MV3 в extension-origin scanner-host, ZIP,
и независимое чтение `threads/77.json` и `source/evidence.json`.
Передача в синтетическом тесте работала. Однако v0.2.0 откладывала
загрузку до накопления 100 утверждённых заказов или конца файла, отчего
у пользователя **не было выгрузок в процессе длинного сканирования**.

В v0.2.1 каждый успешно обработанный утверждённый заказ немедленно
формирует **свой ZIP**. Структура содержимого не упрощалась:
`manifest.json`, `index/orders.json`,
`orders/<номер>/source/evidence.json` и `backup.json`,
`threads/<item_id>.json`, `approvals.json`, `articles.json`,
`files-index.json`, `assets/<sha256>.<ext>`, `review.json`.
Подтверждение SHA-256/CRC и связей автор/сообщение/файл — прежнее.

## Выбор папки
**До начала сканирования выбор обязательный** — отсутствие конфигурации
выдаёт `VISION_ARCHIVE_FOLDER_NOT_CONFIGURED` и сканирование не запускает.

Два варианта:
1. С портала через панель Vision AI выбрать «Автоматически в подпапку
   Загрузок», ввести название подпапки (напр. `VisionAI`), «Применить».
   Chrome Downloads API сохраняет туда по одному ZIP на заказ.
   Результат подтверждается состоянием Chrome COMPLETE и размером.
2. Нажать «Выбрать папку на диске…», в открывшейся отдельной вкладке
   расширения повторно нажать «Выбрать папку на диске…».
   Срабатывает File System Access `showDirectoryPicker` по явному клику.
   Дескриптор папки с разрешением на запись сохраняется в IndexedDB
   расширения. ZIP пишется напрямую в папку через `createWritable`,
   затем независимо перечитывается и проверяется SHA-256. Реестр ведёт
   запись `DIRECTORY_VERIFIED` со всеми параметрами.
   Если Chrome отозвал разрешение, сканирование блокируется до повторного
   выбора. Не нужен вызов диалога сохранения для каждого заказа.
   Если `showDirectoryPicker` в конкретном Chrome недоступен, оставлен
   первый вариант (подпапка Downloads).
   
Настройки пути нельзя переносить на другой ПК: путь не передаётся на сайт
или в GitHub. Запись с тем же именем и другой контрольной суммой не
перезаписывается — выбирается `.copy-N.zip`. Для повторного подтверждения
существующего файла в выбранной папке делается SHA-256 сверка.

## Надёжность
- Сохранена атомарная IndexedDB запись «материалы заказа + следующий курсор».
- Очередной заказ не удаляется из непроверенной партии до подтверждения ZIP.
- Если сеанс оборван во время записи ZIP, журнал `stage=preparing`
  и исходные bytes позволяют безопасно повторить/подтвердить запись.
- Существующие невыгруженные батчи v0.2.0 по возможности выводятся
  по одному заказу при восстановлении; целевые старые данные не очищаются.
- Если сервер вернул ошибку авторизации или не передал обсуждение,
  такой заказ попадает в журнал проблем, не имитируя успешную выгрузку.
- Никаких production/POST и автоматического снятия предупреждений Chrome.

## Установка и ручная приёмка
Перед обновлением **не очищать** данные расширения и тестового сайта.
Скачать ZIP только после зелёного Publish CI.
Распаковать поверх прежней папки, обновить unpacked extension и
обновить страницу тестового домена. Выбрать папку до запуска.
Проверить один реальный утверждённый заказ, посмотреть ZIP на диске:
`source/evidence.json` должен содержать сообщения, а
`threads/<item>.json` историю автора/замечания.
Проверить доступность бинарных файлов по `files-index.json` и
`manifest.json` (не считать недоступное вложение полученным).
При невозможности получить конкретный файл сохранить MANUAL-статус.
В CI нет доступа к живой тестовой LAN-сессии.
