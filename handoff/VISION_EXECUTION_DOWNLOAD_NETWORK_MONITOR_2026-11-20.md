## Исходная постановка
Панель должна запускаться на любой авторизованной странице
psk.testgifts.local или testgifts.local, проверяя
http://testgifts.local/private/order/{семизначный номер}.
Добавить: контроль выполнения, контроль сохранения, кнопки
сброса и останова, прямые GET без открытия страницы там, где возможно,
контроль ошибок сети.

## Реализовано
1. vision/orders/approval-network-control.mjs: контролируемый GET.
   Три повтора после первичной неудачи, задержки 400/800/1200 мс,
   после шести последовательных сетевых ошибок — circuit_open.
   HTTP 401/403 и перенаправление на авторизацию прекращают сканирование,
   HTTP 429 также останавливает обработку. Отдельные 404/410 и
   неподтверждённые заказы пропускаются без сетевых повторов.
2. В обоих сканерах telemetry network (попытки/повторы/сбои подряд,
   состояние, последняя успешная проверка, HTTP-код) сохраняется
   в IndexedDB журнале или контрольной точке. При 6 ошибках подряд
   очередь ставится на паузу, а не пробегает дальше миллионы номеров.
3. Для каждого номера сначала выполняется GET статуса 59
   с инертным разбором HTML без открытия отдельной вкладки.
   Только для одобренных заказов с динамическими согласованиями
   текущая система использует скрытую вкладку браузера.
   Опасные POST, обход авторизации и неразрешённые HTTP URL не добавлены.
4. Удалённая панель vision-order-launcher.js показывает
   обработано/всего/процент, этап, последнее действие, прямые GET
   против браузерных карточек, сетевые ошибки/повторы/HTTP-статус,
   количество подготовленных и подтверждённых файлов.
5. Контроль ZIP: сведения о партии из финального манифеста
   (files_verified, files_missing, entry_count, bytes) сохраняются
   в состоянии до загрузки. Chrome Downloads проверяет точный размер,
   имя и завершённый статус. Последний успешный ZIP фиксируется
   с временем подтверждения, размером и числом файлов.
   Новый контрол «Проверить сохранение ZIP» обновляет статус.
6. Управление: кнопка «Остановить» останавливает после текущего заказа,
   сохраняет курсор и исходные вложения в IndexedDB, не навязывая ZIP.
   Отдельно работает «Сохранить ZIP». «Сбросить прогресс» запрашивает
   подтверждение на активной странице пользователя, недоступно во время
   работающего сканирования и очищает только выбранную очередь/режим.
7. Внутренний контроллер service-worker пересылает команду reset
   исключительно с allowlisted test-origin на каноническую вкладку.
8. Версия Chrome extension manifest — 0.1.16.

## Предохранители
- При неподтверждённом скачивании ZIP данные партии сохраняются.
- Chrome Safe Browsing не отключается и опасные ZIP не принимаются
  автоматически. При блокировке пользователь видит реальный статус.
- Сетевые ошибки не выдаются за утверждённые или просмотренные заказы.
- После паузы/останова не стирать данные и не автопродолжать режим.
- Тесты используют только синтетические заказы/вложения; нельзя
  отправлять реальный TXT или переписки в публичный GitHub.
