## 2. ПОСЛЕДНЯЯ ЗАДАЧА — чтение уже загруженных макетов из gifts.ru

Пользователь просил: при каждом обновлении корзины проверять файлы, уже добавленные в **«Макеты для заказа» → «Загрузка макетов»**, и делать их доступными в Макетной для редактирования. **НЕ использовать «Согласование макетов»**.

Пример — заказ **8006776** (предоставлен сохранённый HTML пользователем). Подтверждены два клиентских PDF:
- `gerb2.pdf` → `8006776_maket_2_201026_143328.pdf`, upload ID `18311644`;
- `che.pdf` → `8006776_maket_1_201026_143328.pdf`, upload ID `18311643`.
Внутренний ID заказа `7824901`, endpoint скачивания `/cart/act/mda?oid=7824901&id=<uploadId>`.
Два заказанных нанесения относятся к одному артикулу `77700.60` (разные order item IDs), а сведения о привязке конкретного загруженного PDF к конкретному нанесению в HTML **не подтверждены**. **НЕЛЬЗЯ** угадывать поле; требуется выбор артикула/поля/файла пользователем.

### Реализация в исходниках и production
- `direct-mode.js` обнаруживает `a[data-maket="true"]` исключительно из раздела uploaded/customer files, проверяет точный gifts URL, oid и upload ID, читает modal AJAX и declarative shadow DOM. `/api/orders/:order` возвращает `uploadedMakets` с `attachmentScope: "order"`, без искусственного item ID или fieldIndex.
- `/api/orders/:order/uploaded-makets/:uploadId.pdf` повторно проверяет права через живую авторизованную страницу заказа, id в whitelist, размер до 40 MB и PDF magic. Клиент не может передать произвольный URL.
- `assets/order-uploaded-makets.js` показывает количество прикреплений в корзине и список в открытом заказе с исходными именами; кнопка **«Открыть для редактирования»** применяет PDF только к явно выбранному реальному полю.
- `tools/patch-order-uploaded-makets.mjs` добавляет `window.gwbUploadedMaketNative`. Перед передачей проверяются номер заказа, артикул, itemId, страница, поле и отсутствие конкурирующей загрузки. Редактор использует штатный `Ai(...,"art")`, сохраняя PrintCheck, CMYK, геометрию, Undo/Redo.
- `tools/build-launcher.mjs`, `editor.html`, `tests/order-uploaded-makets.test.mjs`, `tests/order-uploaded-makets-browser.mjs`, CI workflow включают доработку.
- Отдельная документация: `handoff/MAKETNAYA_UPLOADED_ORDER_MAKETS_2026-10-20.md` и `handoff/MAKETNAYA_GIFTS_UPLOADED_MAKETS_2026-10-20.md`.

## 4. Схема проекта, история функциональности
- gifts.ru → `direct-mode.js` → чтение корзины/заказа/конструкторов/клиентских вложений → `editor.html` + `assets/index-BpU9kvz8.js`.
- Редактирование макета: артикул → точное место с кодом → реальное поле шаблона → логотип → PrintCheck → PDF.
- Добавление из Проводника с подсветкой поля, Undo/Redo, полностраничный/field режимы.
- Редакторы логотипа: VectorCraft и TraceDraw (Rust/WASM), анимированный выбор ангел/чертёнок, возврат логотипа с размерами/CMYK через нативный PDF (SVG для геометрии). ICC/spot требуют дополнительных тестов.
- «Редактор мокапов»: реальные фото с gifts.ru, сохраняемые привязки фото↔поле, цилиндры с развёрткой и перспективой.
- PrintCheck: позитивные/негативные минимальные элементы, зазоры, разрешение, безопасное поле, цветовые модели, количество цветов. Технические сложные тест-кейсы остаются открытыми.
- Ранние требования и все этапы сентября—октября см. `MAKETNAYA_FULL_DEVELOPMENT_HISTORY_2026-10-20.md` в архиве пользователя. Есть иллюстрированный PDF-мануал.
