## Требование

«Сделай возможность перезаписи файла макета из Макетной. Сохранить или сохранить как».

## Действующее поведение

В простом и расширенном интерфейсе рядом с экспортом готовы две кнопки: **«Сохранить»** и **«Сохранить как…»**.

- Если пользователь выбрал поле нанесения и открыл **существующий PDF Макетной** из списка макетов заказа для редактирования, программа запоминает **строго ID этого PDF, реальное имя, order ID, артикул, itemId, ссылку на текущий объект конструктора и выбранную запись**. Нельзя по совпадению имени/артикула выбрать другой макет.
- **«Сохранить»** после редактирования выбранного PDF открывает подтверждение перезаписи. Создаётся новая PDF-версия, загружается в этот же заказ и подтверждается **НОВЫМ ID**, затем сервер проверяет наличие обеих версий и штатное разрешение на удаление **только выбранного старого ID**, и после этого удаляет старый.
- После удачной замены версия с новым ID становится активным источником для следующего «Сохранить».
- **«Сохранить как…»** запрашивает новое имя PDF, предлагает `_копия.pdf` при наличии ранее открытого оригинала и запрещает совпадение имени с известными макетами заказа; загружает отдельный файл с подтверждением. Оригиналы не удаляются.
- Если пользователь ещё не редактирует файл, ранее открытый из списка макетов, **«Сохранить»** ведёт себя как **«Сохранить как…»**.
- При переходе к другому файлу редактирования связь со старым ID сбрасывается, в том числе для стороннего PDF, который открывается только в VectorCraft/TraceDraw. При смене заказа, артикула или конструктора автоматическая перезапись не допускается: ключи исходной записи должны совпадать.
- Под кнопками видна подпись «Редактируется: <имя PDF>», в списке исходник дополнительно выделяется рамкой и пометкой.
- При ожидании запроса обе кнопки временно блокируются. Старый PDF не удаляется при неподтверждённой загрузке или неопределённом ответе.

## Важно об устройстве gifts.ru

У gifts.ru пока **не подтверждён атомарный endpoint перезаписи PDF**, поэтому серверная операция не атомарна. Реализован безопасный двухшаговый процесс, **upload new, verify new attachment ID, revalidate old, delete selected old**.

При ошибке на этапе удаления обе версии остаются в заказе, ответ имеет `partial: true` и `newId` и UI явно показывает предупреждение. При неопределённом HTTP-ответе следует проверить вложения заказа перед повторной отправкой. Массовое удаление по `data-id=-111` никогда не выполняется.

Это обновление *вложения заказа* по его ID, а не изменение PDF-файла непосредственно на диске пользователя. В браузере невозможно без отдельного доступа незаметно перезаписывать ранее скачанный локальный PDF.

## Изменённые файлы

- `assets/order-uploaded-makets.js`: «Сохранить / Сохранить как…», диалог нового имени, подтверждение перезаписи, привязка к ранее открытому PDF и статус частичного завершения, обновление списка.
- `direct-mode.js`: `PUT /api/orders/:order/uploaded-makets/:fileId` валидирует ID/исходное имя/право удаления и новый PDF; переиспользует существующий `apiUploadReadyMaket` и `apiDeleteUploadedMaket` строго в последовательности после подтверждения нового ID; предотвращает удаление невыбранного файла.
- `tests/order-uploaded-makets-browser.mjs`: проверка Save As, Save в тот же заказ с заменой только нужного ID, отказ неверному оригинальному имени, проверка частичного сохранения, когда gifts.ru отклонил удаление, и сохранность остальных PDF.

Все прочие модули Макетной, VectorCraft, TraceDraw, PrintCheck, редактор мокапов и их цвета/CMYK не переработаны.

## Верификация и ограничения

Проверено с имитацией реального HTML gifts.ru заказа №8006776 и серверных endpoint: вставка/удаление ID, в том числе отклонение удаления. **Реальные вложения gifts.ru не редактировались и не удалялись**: операция удаления требует проверки в пользовательской авторизованной сессии. Текущий механизм удаления сохраняет проверки `j_delete_maket` из корзины gifts.ru.
