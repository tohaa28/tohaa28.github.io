# Макетная — единые серверные настройки нанесений (15 октября 2026)

## Запрос и принцип
Все параметры технологий печати должны храниться на сервере, действовать одинаково для каждого пользователя и не зависеть от конкретного браузера. Ранее настройки хранились в `localStorage["gwb-method-settings-v1"]` на origin gifts.ru, поэтому были доступны только на устройстве администратора.

## Каноническое хранение
**Источник правды**: `method-settings.json` в исходной ветке `gifts-layout-workbench-mockups-source` репозитория `tohaa28/tohaa28.github.io`.
Опубликованная копия: `https://tohaa28.github.io/gifts-layout-workbench-mockups/method-settings.json`.

Формат совместим с предыдущим: `{"version":1,"methods":{}}` со всеми старыми опциональными значениями для каждого кода.
**Важно**: на момент внедрения исходный серверный файл содержит ПУСТОЙ словарь `methods`. Прежние пользовательские настройки нельзя автоматически перенести с неизвестного локального компьютера; оператор с доступом к исходному браузеру должен выполнить явный импорт прежнего `localStorage` через кнопку и сохранить на GitHub. До такой миграции все пользователи используют одинаковые исходные нормы и автоматические алгоритмы, а не частные переопределения, которые могли существовать в отдельных браузерах.

## Файлы и реализация
- `assets/method-settings-server.mjs`: `fetchMethodSettings` читает общий raw-файл через публичное HTTPS без токена, запасной путь — GitHub Pages; запросы `cache:no-store` и параметр против кэша. `commitMethodSettings` читает текущий объект и SHA по GitHub Contents API с токеном `Contents: Read and write`, валидирует ревизию относительно черновика и записывает только при отсутствии чужих изменений (SHA optimistic concurrency). Токен никогда не сохраняется в файлах, localStorage или URL.
- `assets/method-settings.mjs`: удалено автоматическое использование localStorage как источника правил. `loadServerSettings()` загружает единый JSON при старте, обновляет при focus и каждые 120 секунд; событие `gwb-method-settings-change` пересчитывает диагностику. `saveSettings(value,{token,previous})` выполняет только подтверждённую сервером запись и затем применяет результат локально. `readLegacyLocalSettings()` исключительно для явной миграции в черновик.
- `assets/method-admin.mjs`: диалог показывает серверный статус, окно ввода GitHub-токена (только память текущего открытого окна), «Сохранить настройки на сервере», «Обновить с сервера», «Загрузить прежние локальные настройки». Пока сервер не вернул актуальные правила, сохранение запрещено; при ошибке записи текущие общие правила не заменяются. Параметры при открытии по-прежнему выбираются по активному месту нанесения и сохраняют все предшествующие ограничения вектора, количества цветов и сопоставления с заказом. Локальный пароль панели не является удостоверением прав на GitHub; сохранение требует реальной авторизации PAT.
- `assets/logo-preflight.mjs`: пока обязательный общий файл не загружен или при ошибке сервера, создаётся `settings-server: bad` для всех загруженных макетов с блокировкой выгрузки, вместо молчаливого применения локальных/устаревших правил.
- `tools/patch-artwork-preflight.mjs`: импортирует актуальные админ/контрольные модули с версией `20261015-server-1`, сохраняет SHA-256 новой сборки `99b12826b63a21be663dcf4ef78f2717748c84604480fc50b6f9162e86903fcc` и fail-closed проверку исходного бандла.
- `.github/workflows/publish-maketnaya-mockups.yml`: следит за `method-settings.json`, валидирует и публикует его в корень проекта GitHub Pages.
- `.github/workflows/test-direct-workbench.yml`: моделирует общий сервер и GitHub API, включая токен, SHA, PUT, и одновременно проверяет загрузку одинаковых настроек во втором браузерном окне. `tests/method-settings-server.test.mjs` тестирует GitHub чтение/запись, конфликт версий и отказ сохранения при ошибках. Предыдущие модульные/браузерные проверки сохранены.
- `docs/method-admin.md`: инструкции пользователю и администратору обновлены.

## Что дальше сделать администратору
1. Открыть Макетную на gifts.ru и войти в настройки Alt+N.
2. Если прежде задавали правила на этом компьютере, нажать «Загрузить прежние локальные настройки» и проверить их. Иначе редактировать непосредственно новые общие параметры.
3. Вставить GitHub fine-grained token с `Contents: Read and write` для `tohaa28/tohaa28.github.io`.
4. Нажать «Сохранить настройки на сервере» и дождаться сообщения с SHA коммита. Публикация GitHub Pages может занять несколько минут, но raw-источник будет читать обновлённый source JSON раньше.
5. Остальные пользователи получат общее правило при новом запуске и периодическом обновлении (до двух минут). При конфликте повторно загрузить текущие общие настройки.

## Ограничения безопасности
GitHub Pages — статическая платформа, поэтому токен GitHub не встроен в приложение. Операторы без прав GitHub могут читать правила, но не изменять сервер. Сохранённые где-либо браузерные локальные токены Редактора мокапов не используются этой новой панелью и не переносятся неявно.
