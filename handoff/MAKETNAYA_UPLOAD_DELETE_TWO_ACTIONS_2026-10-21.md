# Макетная — удаление загруженных макетов и режимы кнопок (21.10.2026)

## Запрос
«В режиме добавления логотипа в выбранное поле у всех макетов должна быть кнопка "Открыть для редактирования". В остальных режимах должны быть две кнопки "Скачать PDF" и "Удалить макет"».

## Реализованное состояние
- В `assets/order-uploaded-makets.js` для каждого загруженного PDF в реальном режиме активного выбранного поля (`gwbUploadedMaketNative.getScope()`, `#fieldLogoTools` и `#zoomPage`) отображается только «Открыть для редактирования».
- В любом другом режиме панели заказа показываются рядом две кнопки — «Скачать PDF» и «Удалить макет». Две равные CSS-grid колонки; длинные имена PDF остаются отдельной строкой над кнопками.
- Удаление требует явного `window.confirm` с конкретным оригинальным именем и номером заказа, блокирует повторный клик до ответа и сообщает об ошибке без ложного статуса успеха.
- В `direct-mode.js` добавлен `DELETE /api/orders/:order/uploaded-makets/:maketId`. Для каждой операции перечитывается защищённый заказ в gifts.ru, проверяются `order`, реальный идентификатор вложения, ненулевой `orderInternalId` и наличие штатного `j_delete_maket[data-id][data-orderid]` **у той же строки PDF**. ID `-111` (удалить ВСЕ) и чужие IDs запрещены. Отдельные кнопки берутся из вкладки «Загрузка макетов», не из вкладки согласования или шаблонов.
- Команда сайта найдена по сохранённому приватному HTML `Заказ 8006776.html`: `Logrus.Order.config.ajaxActions.deleteMaket.url = /ajax/gifts/order?action=delete_maket&type=10`; реальный элемент имеет `data-id` и `data-orderid`. Используется запрос `GET` к этой команде с `id=<fileId>&orderid=<internalId>`. Скрытый массовый `data-id=-111` никогда не вызывается.
- Успех объявляется только после повторного чтения заказа и исчезновения ровно этого вложения из свежих данных. При неподтверждённом результате UI выдаёт предупреждение с просьбой проверить список. Оригинальное содержимое другого PDF и остальные инструменты не изменяются.
- Допускаются абсолютная или относительная `#`-ссылка штатной кнопки удаления, но она должна разрешаться только в путь конкретного заказа gifts.ru.

## Проверки
`tests/order-uploaded-makets-browser.mjs` проверяет 300px ширину карточки, два действия в одном ряду в обычном режиме, одно действие в режиме поля, исчезновение удаления в режиме поля, отмену подтверждения без запроса на сервер, отказ чужому ID, добавление нового готового PDF и последующее выборочное удаление только исходного `gerb2.pdf` из смоделированного заказа 8006776. Два остальных файла должны сохраняться, счётчик должен изменяться точно.

GitHub Actions workflow `Publish Maketnaya with Mockups`, run: https://github.com/tohaa28/tohaa28.github.io/actions/runs/39560085307. Precheck SUCCESS и публикация SUCCESS; заключительный большой browser_verify — уточнить по статусу GitHub при продолжении.

**Удаление реального файла на gifts.ru не проверялось и не выполнялось.** E2E тесты используют заглушки официальных endpoints. Если сайт изменит семантику удаления, необходимо проверить HTTP запрос в DevTools на авторизованном тестовом заказе без удаления чужих файлов.
