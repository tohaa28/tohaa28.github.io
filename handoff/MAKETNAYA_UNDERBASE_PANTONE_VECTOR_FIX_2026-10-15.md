# Макетная — H1 Деколь: растровый логотип при «подложка; пантон» (15.10.2026)

## Найденная ошибка
Пользователь предоставил скриншот заказа №8023221, артикул 7224.14, нанесение `H1: Деколь,1`, место `напротив от ручки [подложка; пантон(Н32446/8435С)]`. В Макетной был загружен растровый логотип (проверка показывала 671 dpi), но формат не считался ошибкой — в кратком отчёте было 0 ошибок.

Корневая причина: `orderInkCountFromPlace()` корректно не мог установить **полное число физических красок** при смеси записи «подложка; пантон» и возвращал `ambiguous-order-colors`. Однако `orderArtworkRequirement()` использовал именно статус полного подсчёта красок, поэтому возвращал `unknown` вместо `vector-only`. Формат недопустимого растрового логотипа оставался лишь ручной проверкой, которая в компактной ошибочной панели не показывается автоматически.

## Исправление
- `assets/order-ink-count.mjs`: проверка векторности **отделена от точного подсчёта красок**. Для требования «только вектор» достаточно присутствия хотя бы одной достоверно указанной печатной краски (например, `пантон(Н32446/8435С)`), даже если в той же скобке есть подложка. Теперь `[подложка; пантон(...)]` и `[подложка; черный]` дают `orderArtworkRequirement(...).policy === 'vector-only'`. Если связь с выбранным полем заказа ненадёжна, остаётся статус `manual`, а не ложное «ОК». Отдельная проверка **полного количества** физических красок и подложки по-прежнему может оставаться `manual` — её не подменяем догадкой, чтобы не исказить тиражные параметры.
- `assets/logo-preflight.mjs`: использует обновлённую версию парсера `order-ink-count.mjs?v=20261015-underbase-1`.
- `tools/patch-artwork-preflight.mjs`: обновлён URL загружаемой предпросмотрной проверки до `logo-preflight.mjs?v=20261015-underbase-1`, чтобы браузер не оставлял старый код из кэша. Целевой SHA-256 скомпилированного редактора `25d1eeacfa2498b55aa0f52abad33b91aa9709486beef8d7b9823bbf1437f454`; базовая проверка защищает остальные модули.
- `tests/order-ink-count.test.mjs`: покрывает точный текст заказанного места с Pantone (латиница/кириллица), подсчёт цветов отдельно от обязательной векторности, только подложку, неоднозначную связь.
- `tests/logo-preflight.test.mjs`: для растрового оригинала  H1 c названным Pantone и подложкой возвращает `artwork-type.bad`, без перечня красок формат растра допускается.
- `tests/method-admin-browser.mjs`: реальный Chromium прогон вызывает новый модуль `checkLogo` для H1 с имитацией исходного PNG в поле 60×50 мм и записью `[подложка; пантон(Н32446/8435С)]`: `artwork-type.status=bad`, `effectiveArtworkPolicy=vector-only`, общий `report.status=bad`; без перечня — `ok`, без проверенной привязки — `manual`. Браузерный интерфейс и другие сценарии также проверены.
