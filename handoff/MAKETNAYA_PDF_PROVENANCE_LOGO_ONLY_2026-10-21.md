# Макетная — распознавание происхождения PDF и раздельное редактирование логотипа (21.10.2026)

## Запрос пользователя

«Сделай определение, что макет подготовлен в Макетной. При редактировании сделанного в Макетной логотипа — отделяй конструктор, а добавляй только логотип. В остальных случаях — переноси макет не в поле шаблона, а сразу открывай в одном из редакторов».

## Реализованное поведение

1. Все **вновь генерируемые** PDF Макетной содержат готовую печатную страницу (конструктор + нанесения), а также самостоятельные PDF-вложения логотипов. Формат: `gwb-maketnaya-source.json` (маркер `gwb-maketnaya-layout-v1`) + `gwb-art-001.pdf`, `gwb-art-002.pdf` и т. д. В метаданных сохраняются исходный заказ, артикул, место/страница, реальные геометрические координаты и номер поля. Одно и то же artwork не дублируется для нескольких размещений.
2. При нажатии «Открыть для редактирования» импортёр PDF.js `getAttachments()` проверяет наличие и корректность служебных исходников, заказ, артикул, поле/страницу. Если всё однозначно — **в поле помещается ТОЛЬКО вложенный PDF логотипа**, без конструктора, рамки поля и таблицы заказа. Физические координаты восстанавливаются относительно выбранного поля, при отличающихся размерах — пропорционально ширине и высоте поля.
3. **Сторонний PDF или старый PDF без подтверждаемого вложения** передаётся целиком в новое `gwbEditorChooser.showWithFile(pdf)`. Пользователь выбирает VectorCraft либо TraceDraw; соответствующий редактор получает оригинальный PDF без предварительной загрузки в поле. Исходный макет в поле остаётся нетронутым до явного переноса результата из редактора.
4. Если служебный маркер есть, но вложение повреждено или не соответствует заказу/полю, никакой автоматической подстановки всей страницы в поле не происходит. Пользователь видит причину и может продолжить редактирование исходного документа в одном из редакторов.
5. Существующая проверка CMYK при **возврате** из VectorCraft/TraceDraw, токены поля и ручное подтверждение применения результата сохранены.

## Критическое ограничение — старые PDF

PDF, экспортированные Макетной **до** этого изменения (например, ранее загруженные `8006776_77700.60_макет.pdf`), не содержат отдельного исходника логотипа. По названию или общему виду документа достоверно отделить конструктор нельзя. Такие PDF открываются в VectorCraft/TraceDraw как сторонние файлы. Реализация алгоритма восстановления legacy-PDF через точное сравнение PDF content streams с исходным PDF конструктора — отдельный этап, НЕ объявлять готовым. Старые исходники не перезаписывать.

## Архитектура

- `assets/maketnaya-pdf-provenance.js` — новое `stamp(doc,placements,PDFLib,svgToPdf,identity)` и `inspectAttachments(attachments,scope)`.
- `tools/patch-maketnaya-provenance.mjs` — применяет однократный патч вызова `stamp` в экспортной функции `hn` **ПОСЛЕ** штатных `applyLogoPreflight`, `applyLogoEditorBridge`, `applyPlacementHistory`, `applyLogoDrop`, `applyUploadedMaketsBridge`. Не редактировать собранный bundle напрямую, иначе сломается контрольная SHA защита preflight.
- `tools/build-launcher.mjs` — вызывает `applyMaketnayaProvenance()` перед stamping версий.
- `editor.html` — загружает module provenance до `assets/index-BpU9kvz8.js`; в srcdoc launcher пути обновляются на GitHub Pages.
- `tools/patch-order-uploaded-makets.mjs` — расширяет bridge `gwbUploadedMaketNative.inspect` через встроенный PDF.js `In(...).promise / getAttachments()`. `apply(file,scope,{sourceField,placement})` корректно восстанавливает относительное размещение, не подменяя чужой заказ и поле.
- `assets/order-uploaded-makets.js` — маршрутизирует каждый выбранный PDF после защищённой загрузки: source capsule -> поле; внешний/legacy -> редактор.
- `assets/logo-editor-choice.js` — `showWithFile(pdf)` сохраняет выбранный файл до действия пользователя, обе карточки редакторов передают PDF в свои host API.
- `assets/vectorcraft-integration.js`, `assets/tracedraw-integration.js` — опциональный аргумент `open(externalFile=null)` позволяет работать с PDF непосредственно, без передачи в поле.
- `tests/maketnaya-provenance.test.mjs` — реальные pdf-lib PDF вложения, сохранённая metadata, однозначный выбор конкретного поля, внешние/повреждённые исходники.
- `tests/order-uploaded-makets-browser.mjs` — приём только отдельного логотипа, восстановление placement, внешний PDF в chooser без изменения поля, прежние тесты удаления, загрузки и корзины.
