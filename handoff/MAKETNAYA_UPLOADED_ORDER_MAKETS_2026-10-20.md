# Макетная — чтение загруженных макетов заказов gifts.ru (20.10.2026)

## Основание
Пользователь прислал HTML страницы заказа 8006776, попросил во время обновления корзины находить файлы из «Макеты для заказа» → «Загрузка макетов» и открывать их для редактирования, не затрагивая «Согласование макетов».
Реальная страница содержит 2 загрузки (оба PDF):
- загрузка id 18311644, имя в gifts: 8006776_maket_2_201026_143328.pdf, исходное имя gerb2.pdf
- загрузка id 18311643, имя в gifts: 8006776_maket_1_201026_143328.pdf, исходное имя che.pdf
Идентификатор заказа для скачивания — внутренний oid 7824901, публичный номер 8006776. Клиентский endpoint: /cart/act/mda?oid=7824901&id=<uploadId>. Эти ссылки *не* совпадают с /drawing?action=getOrderItemPdf&orderitemid=... — последняя схема используется только для конструкторов. В заказе несколько нанесений одного артикула, но у загруженных файлов нет однозначных метаданных соответствия конкретному нанесению. Привязка к полю — только явным выбором пользователя.

## Архитектура
1. direct-mode.js: `extractUploadedMakets` ищет атрибут `data-maket="true"`, точный URL `/cart/act/mda`, сверяет oid, извлекает исходные имена и id, читает в том числе declarative shadow DOM `template.content`. Реальные файлы учитываются и с order HTML, и из AJAX `/ajax/gifts/order?action=makets_popup&oid=...`; шаблоны и ссылки согласования исключены. `getOrder` включает `uploadedMakets`, не присваивая ему `itemId` или fieldIndex.
2. API `/api/orders/{order}/uploaded-makets/{uploadId}.pdf`: проверяет авторизацию и свежий список файлов заказа, скачивает от имени авторизованного пользователя с gifts.ru, проверяет PDF magic, размер не более 40 МБ, отказывает на чужом uploadId. Никаких внешних произвольных URL из клиента и никакого редактирования оригинального файла на gifts.ru.
3. assets/order-uploaded-makets.js: корзина показывает количество загруженных макетов, в открытом заказе — две отдельные позиции с исходными названиями. В редакторе вручную выбирают артикул, поле и конкретный загруженный PDF. Обновление корзины обновляет файл-лист; ручной номер заказа тоже поддержан.
4. tools/patch-order-uploaded-makets.mjs: fail-closed native bridge `window.gwbUploadedMaketNative`, который проверяет order/article/item/selected field/page до/после скачивания и использует штатный `Ai(..., "art")`, так что геометрия, PDF/CMYK, PrintCheck и Undo/Redo продолжают работать без второго загрузчика и без подмены input.files.
5. tools/build-launcher.mjs: применяет этот мост после `applyLogoDrop` и перед публикацией. `editor.html` подключает UI, script cache key `order-files-2`. Изменения публикуются в main одновременно для web editor и двух bookmarklet.

## Ограничения
- В текущей реализации открытие в редакторе поддержано для PDF до 40 МБ. Метаданные других форматов могут обнаруживаться, но UI предлагает редактирование только PDF. CDR следует заранее преобразовать в поддерживаемый формат. Если клиентский PDF содержит целый лист конструктора, а не только логотип, его автоматическое выделение из общего листа не реализовано; пользователь выбирает поле вручную.
- Файлы gifts.ru не перезаписываются автоматически — редактируется копия в Макетной.
