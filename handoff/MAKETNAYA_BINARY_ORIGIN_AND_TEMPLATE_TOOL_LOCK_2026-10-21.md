# Макетная — переносимое происхождение PDF и блокировка редактирования при выборе шаблона

**Дата:** 21.10.2026  
**Опубликованная сборка:** `Макетная rd3a11e5e`  
**GitHub Actions:** https://github.com/tohaa28/tohaa28.github.io/actions/runs/39577444946

## Требования

1. В режиме выбора шаблона и при отсутствии выделенного поля **все инструменты редактирования логотипа неактивны**. Выбор изделия, шаблона и самого поля должен оставаться доступным.
2. У PDF, созданного Макетной, показывать небольшой зелёный значок «М» перед названием в блоке загруженных макетов gifts.ru.
3. **Самодостаточный PDF** должен переносить сведения о происхождении, заказе, поле и отдельные исходники логотипов между любыми экземплярами Макетной. Сведения не должны быть записаны открытым текстом в полях `Producer`/`Subject` или JSON-вложении.

## Реализация

### Служебный бинарный блок внутри самого PDF

В `assets/maketnaya-pdf-provenance.js` добавлен **формат 2**:

- бинарное вложение `e0002.dat` (`application/octet-stream`) содержит ограниченный по размеру GZIP-пакет компактных полей JSON, не читаемый как обычный текст без декомпрессии;
- оригинальные PDF логотипов располагаются в самостоятельных нейтрально названных бинарных вложениях `e0001.bin`, `e0002.bin` и т. д., с SHA-256-контрольными суммами содержимого;
- компактные поля сохраняют идентификаторы заказа/артикула, номер страницы/поля, исходные координаты поля, трансформацию и обрезку логотипа;
- макет на видимой PDF-странице остаётся без изменений, с исходным конструктором;
- `stamp` не помещает название программы и открытую структуру в `Producer`/`Subject`;
- `identifyAttachments` позволяет узнать происхождение по содержимому без выбранного поля, `inspectAttachments` извлекает **только исходный логотип для точно совпавшего поля**;
- сохранена обратная совместимость с ранее использованным открытым `gwb-maketnaya-source.json` формата 1;
- ещё более старые файлы без вложения не распознаются по одному имени/виду и направляются в редактор;
- контрольные суммы **не являются цифровой подписью производителя**, а GZIP **не является шифрованием**. Это переносимая техническая идентификация, не способ скрыть содержание от целенаправленного анализа.

Файл `tools/patch-maketnaya-provenance.mjs` теперь вызывает `stamp` перед финальным `h.save()`, а не полагается на локальный IndexedDB sidecar. Старый `assets/maketnaya-pdf-sidecar.js` остался на месте только для совместимости с ранее созданными в этом браузере PDF без вложенных данных.

### Значок Макетной

`tools/patch-order-uploaded-makets.mjs` расширяет нативный мост методом `gwbUploadedMaketNative.identify(bytes)`, используя встроенный PDF.js `getAttachments()`. `assets/order-uploaded-makets.js` при показе PDF в выбранном заказе асинхронно получает файл из **уже разрешённого** gifts.ru GET-endpoint и проверяет его PDF-вложения. Только подтверждённый PDF получает происхождение `maketnaya` и зелёную пиктограмму «М» рядом с именем. В прежнем браузере возможна отметка старых файлов через локальный реестр. Результаты запоминаются для текущего списка файлов, повторное считывание происходит при обновлении корзины. Внесены также изменения в сообщение после загрузки готового PDF: статус опирается на анализ содержимого PDF.

### Блокировка инструментов

Новый `assets/template-selection-tool-lock.js`, подключённый в `editor.html`, определяет активность редактирования одновременно по режиму `orderEditor`, шагу 3, панели `fieldLogoTools` и состоянию кнопки возврата `zoomPage`. При отсутствии выбранного поля блокирует `disabled` и `aria-disabled` для загрузки логотипа, открытия обоих редакторов, Undo/Redo, поворота, масштабирования, центровки, обрезки, размеров, удаления логотипа и добавления во все поля как в простом, так и в подробном режиме. Слежение за изменениями DOM защищает от обратного включения нативными обработчиками. При выборе поля восстанавливается состояние с вызовом штатного `gwbRefreshEditorState()`. **Выбор шаблона/поля и ручная обводка поля не блокируются**.

## Итоговое исправление после публикации — проверено 21.10.2026

Ранний выпуск `rd3a11e5e` был опубликован, но полный browser_verify обнаружил регрессию: в режиме выбранного поля `#editorClip` имел `disabled=false`, однако оставалось `aria-disabled="true"`; браузерные сценарии не могли включить обрезку. Сборку нельзя считать полностью проверенной.

Причина: блокировка `assets/template-selection-tool-lock.js` выставляла `aria-disabled=true` при выборе шаблона и при некоторых последовательностях MutationObserver не снимала этот атрибут при возврате в режим логотипа. Дополнительно нативный движок `X()` ранее не имел публичного способа повторно синхронизировать кнопки.

Исправлено:

1. Последний патч `tools/patch-maketnaya-provenance.mjs` публикует `window.gwbRefreshEditorState=()=>X()` после штатных защищённых патчей; прямое изменение исходного minified bundle не требуется.
2. При выходе из выбора шаблона `assets/template-selection-tool-lock.js` всегда удаляет прежний `aria-disabled` для всех управляемых инструментов, независимо от того, было ли предыдущее состояние записано в `former`; затем вызывается нативная синхронизация кнопок.
3. Браузерный интеграционный тест `tests/pdf-labels-browser.mjs` проверил реальное включение `#editorClip`, SVG-логотип, экспорт PDF и обрезку по повернутой геометрии поля.
