# Принципы работы проекта «Макетная + Редактор мокапов + PrintCheck»
Дата: 2026-10-13

## 1. Источник истины
- Для данных заказа источник истины — свежая страница gifts.ru.
- Для связей шаблонов — «Макеты для заказа» → «Шаблоны макетов».
- Для исходников — каноническая source-ветка GitHub.
- Для пользовательских mockup mapping — свежий `mockup-profiles.json`.
- Для опубликованного состояния — `main` + фактический GitHub Pages deploy.
- Не путать source HEAD, generated main и сохранённые main-only rollback commits.

## 2. Минимальная область изменения
Любая задача должна менять только относящуюся к ней подсистему.
UI корзины не должен менять PrintCheck.
PrintCheck не должен менять мокапы.
Мокапы не должны ломать PDF/заказ/поле.
При сомнении — сначала сравнить до/после и добавить regression.

## 3. Никаких придуманных данных
Нельзя:
- придумывать place;
- заменять точное название общим «лицо/оборот»;
- придумывать поле;
- создавать synthetic field;
- угадывать article↔template при наличии авторитетной связи;
- использовать stale cart вместо свежего gifts.ru.

## 4. Сохранность mapping
Перед ЛЮБОЙ операцией, способной публиковать/откатывать интерфейс:
1. fetch fresh source HEAD;
2. fetch fresh `mockup-profiles.json`;
3. сохранить его blob SHA;
4. при rollback переносить текущий профильный blob в возвращаемое UI-дерево;
5. не force-push вслепую.

UI rollback никогда не является разрешением откатить пользовательские mapping.

## 5. Git discipline
- создавать rollback branch перед значимой правкой;
- commit логическими шагами;
- использовать expected SHA / force-with-lease только когда требуется точный ref update;
- не утверждать успешную публикацию до завершения workflow;
- docs-only commits отличать от functional commits;
- если main был исправлен вручную, обязательно перенести изменение в source, иначе следующий publish source его затрёт.

## 6. Launcher/srcdoc
Критический риск: launcher содержит большой `frame.srcdoc`.
- ручные кавычки/escape могут сломать весь launcher;
- после любого изменения проверять синтаксис launcher;
- канонически launcher должен генерироваться builder’ом;
- если временно правился generated launcher/main, это обязательно зафиксировать как divergence и перенести в source.

## 7. UI заказов
- заказы сначала компактны;
- первый артикул многопозиционного заказа всегда виден;
- остальные раскрываются плавно;
- hover раскрывает, стрелка декоративная;
- одна позиция без стрелки;
- высота карточек одной grid-строки равна максимальной;
- название/тираж/нанесение/place не терять;
- thumbnails lazy-load без `img.hidden=true`;
- mockup badge не накладывается на quantity;
- число позиций остаётся справа в своей зоне;
- если дата показывается, она идёт сразу после номера normal-weight, а не прижимается вправо.

## 8. UI редактора
- максимально простой пошаговый интерфейс;
- тонкие настройки доступны углублением, но не мешают основному пути;
- шаг 1: компактно, 10px details, один внешний frame;
- шаг 2 только после артикула;
- шаг 3 внутри editor;
- шаг 4/download только после artwork;
- physical dimensions, angle, scale, selected field должны переживать UI navigation;
- не растягивать preview.

## 9. Поля/шаблоны
- [print1], [print2], ... по порядку;
- real shape, не bbox;
- colored field → primary;
- ~98% opacity shape → fallback;
- исключить сервисную зелёную область и таблицу;
- arbitrary shape orientation только для удобства просмотра и только нужного поля;
- размеры должны быть физически корректными;
- multi-page PDF и несколько импринтов должны поддерживаться.

## 10. PrintCheck
- алгоритм v25 защищён от случайных UI-правок;
- small elements через физическую геометрию/контрольный круг;
- positive/negative внутри одной краски;
- границы разных красок не дефект;
- угловое схождение не дефект само по себе;
- raster/vector приводятся к общей модели;
- pending status видим;
- не объявлять реальный customer case исправленным только по unit tests.

## 11. Mockup rendering
- не добавлять искусственный background;
- preview = export geometry;
- cylinder preserves artwork proportions;
- mesh seams не должны появляться;
- out-of-frame coordinates допустимы;
- одно поле → много фото и одно фото → много полей;
- каждое фото экспортируется отдельно;
- mapping сохраняется точным profileKey.

## 12. Secrets
- PAT не хранить в Git;
- использовать существующий local bridge/token expiration;
- при отказе token запросить новый;
- не публиковать клиентские оригиналы, тестовые изображения и секреты.

## 13. Анимации
- стартовая сцена и переход в Mockup Editor — часть принятого UX;
- Studio UI 2.0 был откатан и не должен возвращаться самопроизвольно;
- переход в mockups называется «Визуализируй это»;
- анимация не должна пересоздавать editor iframe и терять состояние;
- движения должны быть прерываемыми/безопасными для повторного входа.

## 14. Проверки перед сообщением пользователю
Проверить:
- source HEAD;
- profile blob;
- unit tests;
- precheck;
- publish;
- browser_verify;
- Pages;
- published marker/version;
- при UI — реальный DOM/скриншот, если есть;
- при rollback — что профили не потеряны.

## 15. Правило нового чата
Новый чат не должен «догадываться», какая ветка актуальна.
Сначала:
- прочитать COMPLETE HANDOFF;
- прочитать PROJECT_HISTORY;
- получить свежие refs;
- определить, продолжает ли пользователь canonical source или архивную main-only UI-линию;
- только потом редактировать.
