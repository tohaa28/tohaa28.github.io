# Макетная — автоматический выбор «вектор / растр» по перечисленным цветам печати в заказе (15.10.2026)

## Запрос
При загрузке логотипа, если **в конкретном месте нанесения заказа перечислены печатные краски**, требовать только чистый вектор. Если **перечня печатных красок нет**, растровое изображение не должно автоматически становиться ошибкой именно по формату исходника. Не путать список красок с цветом изделия, соседними местами нанесения и простым числом «2 цвета».

## Резервная точка
До изменения исходный HEAD `d7dff5b973ff49fd16876b3d699495a0e90d3819`; резервная ветка `backup-before-auto-vector-by-order-inks-20261015-d7dff5b`. Сохранённые фото-привязки в `mockup-profiles.json` при любых откатах не перезаписывать.

## Реализация
- `assets/order-ink-count.mjs`: отдельная `orderArtworkRequirement(place,{bindingReliable})`. Включает «только вектор» только для подтверждённого списка красок в квадратных скобках (свойство `orderInkCountFromPlace(...).source === 'order-place-inks'`), например `сторона а [черный(403/Black)]` или `сторона b [черный(Black); белый(White)]`. Отсутствие списка, товарный цвет и запись лишь `2 цвета` дают `any`. Неоднозначные списки или ненадёжное соответствие поля заказу дают `unknown` (ручная проверка, без ложного автоматического допуска).
- `assets/method-settings.mjs`: режим `auto-order-colors` — теперь исходное значение для методов без явно сохранённого `artworkPolicy`. Существующие значения `any` и `vector-only` остаются без изменений. Администратор может явно установить `auto-order-colors`. Формат JSON остаётся `version:1`, старые пользовательские настройки совместимы.
- `assets/logo-preflight.mjs`: в `checkLogo()` для `auto-order-colors` вычисляется `effectiveArtworkPolicy` для **каждого поля с его `orderPlace` и `orderBindingReliable`**. Если источник raster/mixed при наличии списка — `artwork-type.bad`, блокировка экспорта. Без перечня — `artwork-type.ok` для растра (пригодность по DPI, цвету, градиентам и прочим правилам проверяется отдельно). При неопределённом соответствии — `artwork-type.manual`. В диагностике сохраняются `artworkPolicy`, `effectiveArtworkPolicy`, `orderInkDetection`, `orderListedColors`.
- `assets/method-admin.mjs`: в «Требование к исходному макету» показаны `По умолчанию: автоматически по цветам заказа`, `Автоматически по перечню цветов заказа` (явно сохранить), `Допускается вектор и растр`, `Всегда только вектор`. Под селектором отображается применённое требование для выбранного поля, если уже есть его диагностика.
- Интеграция `tools/patch-artwork-preflight.mjs` импортирует `method-admin.mjs?v=20261015-auto-artwork-1` и `logo-preflight.mjs?v=20261015-auto-artwork-1`, которые используют те же свежие настройки, и содержит подтверждённую сборочную SHA-256 `da4de28e4e35dedd027d351c58aadf77e07970adeeee35c4078f4fd3de5641d6`.
- Исправлена детерминированность браузерного теста: `.github/workflows/test-direct-workbench.yml` подаёт JS/CSS из текущего Git checkout для iframe, а не из временно закэшированного Cloudflare/GitHub Pages CDN. Продуктовый код на CDN публикуется обычным процессом.

## Важно
Автоматическое требование относится только к наличию **перечня печатных красок**. Отдельные ограничения по максимальному количеству красок, совпадению с заказом, DPI, цветовой модели и прозрачности работают независимо. Администраторские явно выбранные `vector-only` и `any` намеренно имеют приоритет над автоматикой.
