# Vision AI v0.2.3 — вернуть ZIP по 100 утверждённых заказов
Дата: 2026-11-23. Репозиторий: tohaa28/tohaa28.github.io.
Рабочая ветка: `feature/printcheck-vision-copy-v01`, PR #4 DRAFT.
Production Макетную не изменять и PR не сливать.

## Причина изменения
v0.2.1 принудительно выполняла `saveBatch` после каждого
успешно собранного утверждённого заказа и применяла `slice(0,1)`.
Пользователь вернул требование «по 100 заказов».

## Политика
- В архив включаются только собранные записи `TZ_APPROVED` с
  сохранённым финальным evidence (переписки, статьи и бинарные
  вложения либо зафиксированные ошибки их чтения).
- `APPROVED_ORDERS_PER_ZIP=100`: полный архив создаётся при
  достижении 100 таких заказов; пропущенные и проблемные не учитываются.
- При окончании списка, «Стоп и архив списка», явном сохранении
  неполной партии формируется ZIP с остатком до 99 заказов.
- «Пауза» и перезагрузка оставляют незавершённую партию в IndexedDB.
  Ранее начатый ZIP в `state.download` подтверждается в Chrome/
  в выбранной папке, только затем переносится в реестр `success`.
- Для предотвращения превышения существующего ограничения
  `BATCH_MAX_BYTES=180_000_000` допускается ранний split при
  120 МБ исходных данных партии. Ошибки записи не удаляют исходники.
- Миграция без удаления прежних `pending`: записи v0.2.2
  продолжают собираться до границы 100, а не архивируются по одной.
- В режиме выбранного каталога при восстановлении незавершённой
  записи проверяется `VISION_LOCAL_ARCHIVE_VERIFIED` до commit.
- Исправление v0.2.2 по штатному `href` с завершающим `#` сохранено,
  вместе с 13-сообщениями и 7 вложениями из синтетического теста.

  записей и разделение по объёму.
- `tests/printcheck-vision-one-order-per-zip.browser.mjs` (историческое

- `tests/printcheck-vision-approval-file-list.browser.mjs`:
  1 утверждённый заказ сохраняется в `pending` при перезагрузке,

  должна остаться зелёной.
- Пользователь обязан назначить папку сохранения до запуска.
- CI не имеет авторизованного доступа к внутреннему Gifts;
