# Макетная — сверка количества печатных цветов с конкретным местом в заказе (15.10.2026)

## Запрос
Для некоторых видов нанесения допустимо только число печатных цветов, указанное в заказе на gifts.ru. В административных настройках для каждого кода нанесения нужна необязательная отдельная проверка **точного соответствия** количества исходных красок загруженного логотипа и конкретного места нанесения в заказе.

## Как работает
- `assets/method-settings.mjs`: независимая от `maxColors` необязательная настройка `methods[CODE].orderColorPolicy` (`off` или `match`, по умолчанию `off`). Отдельный контроль `CHECKS.orderColors` может быть выключен, остальные проверки не затрагиваются. Старые JSON настройки `version:1` полностью совместимы.
- `assets/method-admin.mjs`: селектор «Сверка цветов с заказом» / «Строго сравнивать с выбранным местом в заказе». Настройки сохраняются, экспортируются и импортируются по выбранному виду нанесения; тип текущего поля определяется автоматически, как раньше.
- `assets/order-ink-count.mjs`: разбирает точное описание **выбранного** места нанесения, например `сторона а [черный(403/Black)]` => 1 краска; `сторона b [черный(Black); белый(White)]` => 2 краски. Допускаются раздельные краски через `;`/`,` и однозначное текстовое количество `2 цвета`. Если указана подложка вперемешку с красками, CMYK без раздельных красок, описание отсутствует или неоднозначно — результат `manual`, без выдуманного количества. **Цвет изделия не считается цветом нанесения.**
- `assets/logo-preflight.mjs` запускает `compareOrderInkCount` для конкретного загруженного логотипа и соответствующего заказа. Отдельное заключение `order-colors` с `required`, `actual`, `orderColors`, `orderText`, `certainty`. Для чистого SVG с подтверждёнными исходными красками: точное равенство => `ok`, несовпадение (меньше либо больше) => `bad` и блокировка экспорта. Для растровых логотипов надёжно выявленное превышение => `bad`; при недостатке точных данных — `manual`, не ложный `ok`. PDF без подтверждённых исходных spot-разделений — также `manual`.
- `tools/patch-artwork-preflight.mjs`: передача `orderPlace` для **того же поля**, где расположен логотип, через `oo(e.fieldIndex)`, и признака достоверного сопоставления `orderBindingReliable`. Не смешивать соседние места нанесения одного артикула. Новые URL-версии `method-admin.mjs?v=20261015-order-ink-1`, `logo-preflight.mjs?v=20261015-order-ink-1`; обновлена защита SHA-256 скомпилированного редактора до `cbceb1608f47a3f0558e36ea0396cc841a8768b6c0d0d7b8ec2638d7d0dbf9f2`.
- Существующая настройка «Количество цветов нанесения / максимум 1–32» остаётся независимой: она ограничивает число сверху, а новая сверка с заказом требует точного равенства.

## Использование
Открыть выбранное место нанесения → Alt+N → войти в настройки → «Сверка цветов с заказом» → «Строго сравнивать с выбранным местом в заказе» → Сохранить.
Для видов нанесения, где цветовые разделения не фиксируются заказом, оставить «Не сравнивать количество с заказом».
