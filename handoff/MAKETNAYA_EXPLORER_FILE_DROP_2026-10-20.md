# Макетная — перетаскивание логотипа из Проводника Windows (20.10.2026)

## Пользовательская задача
Загружать логотип прямо на нужное поле нанесения конструктора перетаскиванием файла с рабочего стола / Проводника, сохраняя прежнюю кнопку «Добавить логотип» и весь пайплайн PrintCheck, исходное положение других полей и свойства печатного PDF.

## Внедрённое поведение
- HTML5 external drag/drop отслеживается над `#stageScroll`, обрабатывается только `DataTransfer.types` с `Files`.
- Над **действительным полем**, содержащим точку курсора, появляется светло-зелёная подсветка с указанием сбросить файл. Если курсор не внутри поля, никакой логотип не добавляется. Для поля произвольной формы попадание определяется **штатным** `gwbPointInField`, а не bounding box.
- Поддерживаются ровно те же форматы, что и штатная загрузка: PDF, PDF-совместимый AI, SVG, PNG, JPG/JPEG; одиночный файл до 40 МБ. CDR/EPS не декодируются и не маскируются под поддерживаемые форматы.
- При попадании в другое поле на текущей странице вызывается штатный `Vn(fieldIndex)`, а затем `Ai({target:{files:[file]}}, "art")`; первый выбирает место, второй выполняет все прежние проверки и fit. Для ручного поля используется текущее состояние без создания synthetic field.
- Против случайного открытия файлов браузером обработчик предотвращает переход страницы на локальный файл при drop вне поля, а в статусе объясняет, куда его перетащить. Системное перемещение размещённого логотипа мышью не затронуто.
- Смена заказа/артикула или загрузка PDF во время операции блокируют перенос; другое поле и исходники оставлены без изменений. Undo/Redo и PrintCheck работают через те же штатные события, а не через отдельный непроверенный обработчик.

## Архитектура и файлы
1. `tools/patch-logo-drop.mjs`: небольшая, идемпотентная, fail-closed вставка **в текущую область состояния с native Ai/Vn/Wn** после основных патчей; добавляет `window.gwbExplorerLogoDrop.inspect/accept`.
2. `assets/logo-drop.js`: изолированный UI/drag-drop с подсветкой, доступными сообщениями и проверкой одного файла; устанавливается после `logo-editor-choice.js`.
3. `tools/build-launcher.mjs`: `applyLogoDrop()` после `applyPlacementHistory()`.
4. `editor.html`: подключение `logo-drop.js?v=20261020-explorer-drop-1`.
5. `tools/stamp-component-versions.mjs`: новая возможность включена в fingerprint версии.
6. `tests/logo-drop.test.mjs`: проверки попадания в нужный fieldIndex, защиты от drop мимо, блокировки busy и ручного поля.
7. `tests/logo-drop-browser.mjs`: Chromium-проверки внешнего File/DragEvent, подсветки, unsupported CDR и drop вне поля; добавлена в precheck release workflow.
