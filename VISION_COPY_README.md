# Макетная — отдельная копия с PrintCheck Vision v0.1

Дата: 2026-11-16. Статус: **экспериментальный интерфейс, не производственная нейросетевая проверка**.

**Отдельная тестовая публикация:** https://tohaa28.github.io/gifts-layout-workbench-vision/

**Экспертная студия (локальная разметка, без прав на обучение):** https://tohaa28.github.io/gifts-layout-workbench-vision/vision-studio.html

## Исходная версия и безопасность

- Репозиторий: \`tohaa28/tohaa28.github.io\`
- Ветка-источник: \`gifts-layout-workbench-mockups-source\`
- Изолированная копия: \`feature/printcheck-vision-copy-v01\`
- Рабочие ветки и текущая версия «Макетной» **не изменены**. В GitHub Pages **добавлен отдельный каталог** `gifts-layout-workbench-vision/`, остальные каталоги не перезаписываются.
- Существующие редакторы, PrintCheck, PrintCheck PDF, VectorCraft/TraceDraw, мокапы, экспорт и обработка заказов не модифицированы.
- Новый модуль не записывает на gifts.ru, не обучает модель на пользовательских макетах, не отправляет изображения на сторонние серверы.

## Что уже реализовано

1. В верхнюю панель добавлена кнопка **PrintCheck Vision**.
2. Выдвижная панель содержит «Сводку», «Изображение», «Протокол».
3. «Сводка» читает только текущий контекст редактора: заказ, артикул, нанесение, поле, размер, название загруженного логотипа. Динамические значения не вставляются как HTML.
4. «Изображение» читает существующие локальные холсты \`templateCanvas\` и \`overlay\`, позволяет увеличивать и изменять центр просмотра. Это НЕ вывод сегментатора.
5. «Протокол» отображает исходные сообщения существующего PrintCheck без изменения его логики.
6. Кнопка «Скачать текстовую сводку» сохраняет локальный TXT с явным статусом «ИИ-проверка не выполнялась».
7. Отдельная страница \`vision-studio.html\` даёт специалисту локальный редактор прямоугольной разметки PNG/JPEG/WEBP с экспортом JSON и SHA-256. Это **не защищённая production-студия**, не используется для обучения и не доступна как действие в пользовательской панели.

## Запуск над авторизованной Gifts.ru — как у основной «Макетной»

**Основной способ запуска:** https://tohaa28.github.io/gifts-layout-workbench-vision/

1. Откройте страницу по ссылке, включите панель закладок (**Ctrl + Shift + B**).
2. Перетащите кнопку **«Макетная Vision — перетащить в закладки»** на панель закладок. Оставьте исходную закладку основной «Макетной» без изменений.
3. Вернитесь на **https://gifts.ru/**, войдите в учётную запись Gifts.ru, если ещё не вошли, и нажмите созданную закладку «Макетная Vision».
4. Копия появится поверх активной страницы Gifts.ru, без перехода на GitHub Pages и без отдельного входа. Повторное нажатие закрывает копию. Если основная Макетная уже открыта, копия предупредит о необходимости закрыть её после сохранения изменений.

Если перетаскивание закладки недоступно, воспользуйтесь кнопкой **«Скопировать код закладки»** на стартовой странице и вставьте код вручную в URL созданной браузерной закладки.

**Почему не следует открывать `editor.html` напрямую:** отдельная вкладка GitHub Pages имеет другой origin, не получает cookies и авторизованную сессию gifts.ru. Рабочая загрузка заказов требует того же origin, что и основная Макетная. Скрипт `launcher.js` из экспериментального каталога загружается непосредственно при нажатии закладки на gifts.ru, создаёт `iframe.srcdoc` с origin gifts.ru и связывает запросы с родительской страницей.

**Ограничение доверия:** внедрённый скрипт исполняется в авторизованном контексте Gifts.ru. Используйте его только из доверенного релизного каталога проекта. Проверка исполнения в реальной пользовательской сессии не выполнялась автоматически: CI использует синтетическую страницу gifts.ru и тестовую HttpOnly cookie без реального аккаунта.

**Автотест:** `tests/printcheck-vision-session-launch.browser.mjs`. Браузерный Playwright проверяет drag/copy-ready bookmarklet, загрузку реального собранного `launcher.js`, то, что `iframe.srcdoc` принадлежит gifts.ru, передачу тестовой HttpOnly cookie в same-origin `fetch`, повторное закрытие и защиту уже открытой основной Макетной. Воспроизведение идёт только на mocked origin, сетевые запросы перехватываются; никаких реальных заказов CI не читает.

## Экспертные инструменты — цикл C3B.3.E

- **Vision Studio:** https://tohaa28.github.io/gifts-layout-workbench-vision/vision-studio.html — локально выберите разрешённое изображение и выделите фиксированные области. Кнопка «Скачать задание для двух экспертов» создаёт слепой JSON: SHA-256 изображения, координаты и неизменяемые идентификаторы регионов. Исходные имена файлов, заметки и типовая классификация подготовителя в задании отсутствуют.
- **Vision Review:** https://tohaa28.github.io/gifts-layout-workbench-vision/vision-review.html — каждый из двух специалистов открывает одно и то же задание и изображение (проверка SHA-256), отмечает дефект, допустимый элемент или невозможность заключения. Результат сохраняется локально с отдельным отпечатком эксперта.
- **Согласование:** локально выполнить команду node vision/dataset/compare-reviews.mjs task.json expertA.json expertB.json report.json. Скрипт отказывается обрабатывать изменённые задания и одинаковые отпечатки экспертов, оставляет разногласия для пересмотра, не перезаписывает готовый отчёт. Согласование имеет предварительный статус; не является удостоверенным ground truth.
- **Исследовательское сравнение:** модуль vision/dataset/compare-region-methods.mjs накладывает кандидатов двух или более алгоритмов на одни и те же ROI с явной матрицей и экспериментальными порогами. Неизвестный масштаб или пограничные размеры — MANUAL. Нулевое число кандидатов не означает годность макета.

**Детальный протокол и ограничения:** docs/C3B3_E_EXPERT_PROTOCOL.md. Данные реальных заказов, изображения и метки не сохраняются на GitHub; CI работает только с синтетическими изображениями. Реальная экспертная приёмка ещё не выполнена.

## C3B.3.F: закрытый подписанный пилот

Новые Node.js утилиты **не размещают клиентские файлы на сайте**. Они запускаются в доверенной локальной среде и требуют двух независимых экспертных ответов, настоящих байтов исходного изображения/макета, доказательств заказа, масштаба и отбора областей, плюс отдельную Ed25519 подпись аудитора с заранее закреплённым отпечатком его открытого ключа.

- `vision/dataset/prepare-pilot-signoff.mjs` — готовит неподписанный черновик; все подтверждения в состоянии false, разногласия не разрешаются автоматически.
- `vision/dataset/pilot-attestation.mjs` — подтверждает источник, связность всех файлов и подпись, затем может сохранить отдельные исследовательские результаты каждого геометрического алгоритма в заранее защищённый локальный каталог.
- `docs/C3B3_F_SIGNED_PILOT.md` — точная инструкция пилота, ограничения безопасности, схема доказательств и команды запуска, включая OpenSSL/Node и Python evaluator.
- `tests/printcheck-vision-pilot-python-e2e.mjs` — синтетический сквозной тест подписанного пилота до реального Python отчёта.

**Внимание:** на текущем этапе реальных удостоверенных независимых экспертных меток нет. Официальной оценки точности реальных заказов или технологического допуска не заявляем. Не загружать реальные макеты, ключи и локальные результаты в публичный GitHub.

## C3B.3.H — независимые контрольные ROI (экспериментальная выборка)

Подготовка экспертного набора теперь требует независимых контрольных областей — не только участков, найденных детектором. Офлайн-модуль vision/dataset/prepare-blind-control-task.mjs берёт предварительный JSON Vision Studio, добавляет воспроизводимые случайные контрольные области (HMAC-SHA256, отдельный приватный seed) и сохраняет **одинаковое слепое задание двум экспертам** вместе с отдельным закрытым планом. До передачи результатов в исследовательский Python evaluator проверяются точные координаты, 25% контрольных ROI, подписанный план и соответствие обеим независимым подписям.

**Не отправляйте в GitHub** реальные заказы, макеты, seed и пакет доказательств. Подробная инструкция с запуском: docs/C3B3_H_BLIND_CONTROLS.md. Новые тесты подключены к резервному CircleCI vision-contract. Фактической экспертной разметки реальных заказов пока нет; никакие производственные OK/ERROR автоматически не выдаются.

## Что пока не реализовано

- Визуальный кодировщик Tiny U-Net, микрозрение, обученная топологическая модель.
- Извлечение локальных фрагментов из векторной геометрии со строгой калибровкой мм.
- Нормативная база по печати с версионированием.
- Production-аутентификация специалистов, ревью и утверждение обучения.
- Полноценный нейросетевой анализ и заключение «годен/не годен»; опубликован только экспериментальный интерфейс, поверх действующего PrintCheck.
