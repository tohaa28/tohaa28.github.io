# Vision Check LAN — локальное расширение Chrome (C3B.3.R)

**Назначение:** штатный Chrome Manifest V3 механизм для чтения карточек заказов
с \`testgifts.local\` из таблицы на \`psk.testgifts.local\` в рамках
авторизованного браузера, когда обычная закладка не может прочитать
междоменный HTTP-ответ из-за CORS. Не меняет серверную политику безопасности.

**Внимание:** этот вариант использует специальные разрешения расширения Chrome.
Устанавливайте его только для вашей тестовой локальной сети. Убедитесь,
что расширение запрашивает только два хоста:
\`http://psk.testgifts.local/*\` и \`http://testgifts.local/*\`.

## Установка на Windows

1. Скачайте \`vision-local-lan-extension.zip\` с
   \`https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-lan-extension.zip\`.
   ZIP содержит **только код** расширения, без оригиналов заказов.
2. Распакуйте архив в отдельную постоянную папку на ПК, например
   \`D:\VisionCheckLab\browser-extension\`. Внутри этой папки должны находиться
   \`manifest.json\`, \`service-worker.js\`, \`content-transport.js\`,
   \`vision-order-overlay.js\` и этот README (не выбирайте каталог уровнем выше).
3. В Chrome откройте \`chrome://extensions\`, включите «Режим разработчика»,
   нажмите «Загрузить распакованное расширение» и укажите указанную папку.
4. Убедитесь, что разрешения сайта ограничены **только двумя точными
   тестовыми HTTP-доменами**. Рабочий сайт Gifts и GitHub в разрешениях
   отсутствуют. Не добавляйте wildcard-разрешения.
5. Откройте (или обновите уже открытую) страницу
   \`http://psk.testgifts.local/devorders?status=140\`, авторизуйтесь на
   соответствующих тестовых ресурсах браузера. Панель Vision появится
   автоматически. **Не запускайте одновременно старую закладку**, чтобы не
   было двух копий панели.
6. Сначала нажмите «Проверить строку» только в одном заказе.
   Скачайте анонимный «Отчёт JSON» и проверьте поле \`stage\` при сбое.
   Если требуется — проверьте авторизацию на \`testgifts.local\` в этом же
   профиле Chrome. Разрешение расширения не заменяет серверную авторизацию
   и не гарантирует, что cookies тестового сайта будут приняты.
7. При положительном результате запустите «Проверить все заказы». Очередь
   последовательно читает все файлы без общей квоты; можно остановить после
   файла и продолжить с той же позиции. При необходимости соберите локальный
   ZIP только экспертно размеченных тестовых оригиналов и импортируйте его
   в \`D:\VisionCheckLab\`.

## Сетевая и техническая модель

- Код расширения упакован локально: MV3 **запрещает удалённые исполняемые
  скрипты**, здесь нет обращения к GitHub Pages для загрузки кода.
- \`content-transport.js\` исполняется как изолированный content script;
  \`vision-order-overlay.js\` отображает статусы поверх таблицы.
- Chrome service worker отвечает только запросам от главного фрейма
  \`psk.testgifts.local/devorders\`, принимает только \`GET\` и только:
  \`/private/order/<цифры>\`,
  \`/ajax/gifts/order?action=makets_popup&oid=<цифры>\`,
  \`/cart/act/mda?oid=<цифры>&id=<цифры>\`.
- Нет POST/DELETE, обхода других доменов, \`/drawing\`, чтения Cookies API,
  публикации макетов и записи данных на сервер.
- Содержимое файла передаётся порционно из фонового процесса Chrome только
  в панель текущей тестовой страницы. Ограничение: 3 МБ на HTML/JSON
  карточки/попапа, 16 МБ на файл, таймаут 15 секунд; пользовательские
  оригиналы не сохраняются в расширении.
- Если сервер требует другой механизм авторизации или изолирует cookies,
  статус останется MANUAL. Не отключайте защиту браузера и не изменяйте
  боевые серверы ради теста.
- Chrome может обновлять модель разрешений; при изменении тестовых URL
  править точный allowlist и заново проверять безопасный контракт.
- JSON отчёты не содержат ID заказа, URL вложений, сырые bytes, cookies.
  Оригиналы ZIP могут быть конфиденциальны: храните **локально**.

## v0.1.1 — чтение открытого «Согласование макета» в карточке артикула

Точное имя кнопки: **«Согласование макета»**, CSS-селектор
`li[data-itemid] a.j_maketadjusting`. В открывшемся окне используются
`#j_maketAdjustingForm` и `#j_maketadjusting_comments_list`.

1. Обновить расширение на v0.1.1 из изолированного ZIP и перезагрузить
   страницу `http://testgifts.local/private/order/<номер>`.
2. Штатной кнопкой сайта **«Согласование макета»** у нужного артикула
   открыть окно. Расширение **не нажимает** кнопку за пользователя.
3. В мини-панели Vision выбрать **«Прочитать открытое согласование»**.
   Результат: число возможных/отмеченных проблем, 13 сообщений против
   27 системных событий в исследованном примере, количество вложений.
4. Выбрать **«Скачать анонимный JSON»** и передать только этот файл.
   Тексты обсуждений, скриншоты, исходные PDF, имена, даты, номера
   заказов и ID артикула в него НЕ включаются.

Данная панель работает **непосредственно на странице одного заказа** и
не делает никаких GET/POST. Скрипт `vision-order-approval.js` отдельно
упакован в расширение и доступен строго только на тестовом домене
`testgifts.local` (маршрут `/private/order/*`). Фоновому сервису
расширения дополнительные права, новые GET-адреса или POST не даются.

Кнопка «Найти обсуждения» на странице общего списка заказов по-прежнему
читает только HTML карточки. Там может **не быть** динамически
загружаемого окна, поэтому отсутствие списка сообщений ≠ отсутствие
замечаний. Для настоящего списка нужно открыть окно в браузере вручную.

В исходном HTML найдены названия API-операций
`load_maketadjusting_editor` и `load_maketadjusting_comments`, но
параметры сетевых вызовов не установлены независимо, поэтому
автоматическая загрузка модального окна через AJAX пока НЕ разрешена.

Число флажков в форме (например 25) — это **доступные шаблоны проблем**,
а не число обнаруженных дефектов. Последовательность 40 записей
содержит комментарии, технические события и добавление/удаление проблем.
Даже отмеченная текущая проблема без привязки к версии PDF не является
подтверждённым обучающим ROI.


## v0.1.2 — автоматический проход по согласованиям в открытом заказе

На `http://testgifts.local/private/order/<номер>` новая кнопка
**«Автообход согласований >1»** запускает последовательное чтение:

1. Найти у каждого артикула `li[data-itemid] a.j_maketadjusting`
   и **целочисленный счётчик `.gifts-badge`**. Счётчик 0/1 или
   неразборчивый: **пропустить без открытия**. Только значение 2+
   разрешает штатное открытие окна.
2. Последовательно нажать только найденную ссылку «Согласование макета»,
   ждать загрузки штатного модального окна с `#j_maketAdjustingForm` и
   `#j_maketadjusting_comments_list`, проверить `oiid` и число сообщений,
   считать историю; затем закрыть открытое окно (только своё).
   **Не нажимать «Сохранить»**, не отправлять сообщения и файлы,
   не вызывать другие страницы или неизвестные endpoints.
3. Собрать в памяти Chrome текущее описание проблем, только отмеченные
   флажки, сообщения, события добавления/удаления, очередность,
   даты (без имён авторов), типы вложений и их `data-id`.
4. **«Остановить обход»** отменяет дальнейшие открытия.
5. **«Сохранить приватные данные»** по отдельному подтверждению скачивает
   `vision-private-approval-evidence.json` только на ПК. Он содержит
   номера заказов, артикулов, тексты сообщений, имена файлов:
   **не отправляйте его в публичные чаты, GitHub, облачные сервисы**.
6. **«Анонимный отчёт обхода»** сохраняет JSON без номеров заказов,
   авторов, текста и имён файлов для анализа работы алгоритма.

Расширение **не загружает содержимое вложений**: разрешённые параметры
их чтения ещё не проверены. Сохранённые имена/ID дают точку привязки
для следующей строго локальной стадии. Бейдж с числом сообщений —
фильтр на открытие, а не доказательство найденного дефекта.
Обучение и допуск к печати остаются выключены.

Ограничения: не более 100 согласований на страницу заказа, не более
1500 сообщений в одном окне, один активный обход в текущей вкладке,
таймаут открытия 16 с. Если другая модалка уже открыта, обход не
закрывает её и требует ручной проверки. Для перехода между разными
заказами пока откройте страницу очередного заказа; скрипт проходит
все подходящие артикулы **внутри неё**.
