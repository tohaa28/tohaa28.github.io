# Vision Check LAN — локальное расширение Chrome (C3B.3.R)

**Назначение:** штатный Chrome Manifest V3 механизм для чтения карточек заказов
с \`testgifts.local\` из таблицы на \`psk.testgifts.local\` в рамках
авторизованного браузера, когда обычная закладка не может прочитать
междоменный HTTP-ответ из-за CORS. Не меняет серверную политику безопасности.

**Внимание:** этот вариант использует специальные разрешения расширения Chrome.
Устанавливайте его только для вашей тестовой локальной сети. Убедитесь,
что расширение запрашивает только два хоста:
\`http://psk.testgifts.local/*\` и \`http://testgifts.local/*\`.

## Установка на Windows

1. Скачайте \`vision-local-lan-extension.zip\` с
   \`https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-lan-extension.zip\`.
   ZIP содержит **только код** расширения, без оригиналов заказов.
2. Распакуйте архив в отдельную постоянную папку на ПК, например
   \`D:\VisionCheckLab\browser-extension\`. Внутри этой папки должны находиться
   \`manifest.json\`, \`service-worker.js\`, \`content-transport.js\`,
   \`vision-order-overlay.js\` и этот README (не выбирайте каталог уровнем выше).
3. В Chrome откройте \`chrome://extensions\`, включите «Режим разработчика»,
   нажмите «Загрузить распакованное расширение» и укажите указанную папку.
4. Убедитесь, что разрешения сайта ограничены **только двумя точными
   тестовыми HTTP-доменами**. Рабочий сайт Gifts и GitHub в разрешениях
   отсутствуют. Не добавляйте wildcard-разрешения.
5. Откройте (или обновите уже открытую) страницу
   \`http://psk.testgifts.local/devorders?status=140\`, авторизуйтесь на
   соответствующих тестовых ресурсах браузера. Панель Vision появится
   автоматически. **Не запускайте одновременно старую закладку**, чтобы не
   было двух копий панели.
6. Сначала нажмите «Проверить строку» только в одном заказе.
   Скачайте анонимный «Отчёт JSON» и проверьте поле \`stage\` при сбое.
   Если требуется — проверьте авторизацию на \`testgifts.local\` в этом же
   профиле Chrome. Разрешение расширения не заменяет серверную авторизацию
   и не гарантирует, что cookies тестового сайта будут приняты.
7. При положительном результате запустите «Проверить все заказы». Очередь
   последовательно читает все файлы без общей квоты; можно остановить после
   файла и продолжить с той же позиции. При необходимости соберите локальный
   ZIP только экспертно размеченных тестовых оригиналов и импортируйте его
   в \`D:\VisionCheckLab\`.

## Сетевая и техническая модель

- Код расширения упакован локально: MV3 **запрещает удалённые исполняемые
  скрипты**, здесь нет обращения к GitHub Pages для загрузки кода.
- \`content-transport.js\` исполняется как изолированный content script;
  \`vision-order-overlay.js\` отображает статусы поверх таблицы.
- Chrome service worker отвечает только запросам от главного фрейма
  \`psk.testgifts.local/devorders\`, принимает только \`GET\` и только:
  \`/private/order/<цифры>\`,
  \`/ajax/gifts/order?action=makets_popup&oid=<цифры>\`,
  \`/cart/act/mda?oid=<цифры>&id=<цифры>\`.
- Нет POST/DELETE, обхода других доменов, \`/drawing\`, чтения Cookies API,
  публикации макетов и записи данных на сервер.
- Содержимое файла передаётся порционно из фонового процесса Chrome только
  в панель текущей тестовой страницы. Ограничение: 3 МБ на HTML/JSON
  карточки/попапа, 16 МБ на файл, таймаут 15 секунд; пользовательские
  оригиналы не сохраняются в расширении.
- Если сервер требует другой механизм авторизации или изолирует cookies,
  статус останется MANUAL. Не отключайте защиту браузера и не изменяйте
  боевые серверы ради теста.
- Chrome может обновлять модель разрешений; при изменении тестовых URL
  править точный allowlist и заново проверять безопасный контракт.
- JSON отчёты не содержат ID заказа, URL вложений, сырые bytes, cookies.
  Оригиналы ZIP могут быть конфиденциальны: храните **локально**.

## v0.1.1 — чтение открытого «Согласование макета» в карточке артикула

Точное имя кнопки: **«Согласование макета»**, CSS-селектор
`li[data-itemid] a.j_maketadjusting`. В открывшемся окне используются
`#j_maketAdjustingForm` и `#j_maketadjusting_comments_list`.

1. Обновить расширение на v0.1.1 из изолированного ZIP и перезагрузить
   страницу `http://testgifts.local/private/order/<номер>`.
2. Штатной кнопкой сайта **«Согласование макета»** у нужного артикула
   открыть окно. Расширение **не нажимает** кнопку за пользователя.
3. В мини-панели Vision выбрать **«Прочитать открытое согласование»**.
   Результат: число возможных/отмеченных проблем, 13 сообщений против
   27 системных событий в исследованном примере, количество вложений.
4. Выбрать **«Скачать анонимный JSON»** и передать только этот файл.
   Тексты обсуждений, скриншоты, исходные PDF, имена, даты, номера
   заказов и ID артикула в него НЕ включаются.

Данная панель работает **непосредственно на странице одного заказа** и
не делает никаких GET/POST. Скрипт `vision-order-approval.js` отдельно
упакован в расширение и доступен строго только на тестовом домене
`testgifts.local` (маршрут `/private/order/*`). Фоновому сервису
расширения дополнительные права, новые GET-адреса или POST не даются.

Кнопка «Найти обсуждения» на странице общего списка заказов по-прежнему
читает только HTML карточки. Там может **не быть** динамически
загружаемого окна, поэтому отсутствие списка сообщений ≠ отсутствие
замечаний. Для настоящего списка нужно открыть окно в браузере вручную.

В исходном HTML найдены названия API-операций
`load_maketadjusting_editor` и `load_maketadjusting_comments`, но
параметры сетевых вызовов не установлены независимо, поэтому
автоматическая загрузка модального окна через AJAX пока НЕ разрешена.

Число флажков в форме (например 25) — это **доступные шаблоны проблем**,
а не число обнаруженных дефектов. Последовательность 40 записей
содержит комментарии, технические события и добавление/удаление проблем.
Даже отмеченная текущая проблема без привязки к версии PDF не является
подтверждённым обучающим ROI.


## v0.1.2 — автоматический проход по согласованиям в открытом заказе

На `http://testgifts.local/private/order/<номер>` новая кнопка
**«Автообход согласований >1»** запускает последовательное чтение:

1. Найти у каждого артикула `li[data-itemid] a.j_maketadjusting`
   и **целочисленный счётчик `.gifts-badge`**. Счётчик 0/1 или
   неразборчивый: **пропустить без открытия**. Только значение 2+
   разрешает штатное открытие окна.
2. Последовательно нажать только найденную ссылку «Согласование макета»,
   ждать загрузки штатного модального окна с `#j_maketAdjustingForm` и
   `#j_maketadjusting_comments_list`, проверить `oiid` и число сообщений,
   считать историю; затем закрыть открытое окно (только своё).
   **Не нажимать «Сохранить»**, не отправлять сообщения и файлы,
   не вызывать другие страницы или неизвестные endpoints.
3. Собрать в памяти Chrome текущее описание проблем, только отмеченные
   флажки, сообщения, события добавления/удаления, очередность,
   даты (без имён авторов), типы вложений и их `data-id`.
4. **«Остановить обход»** отменяет дальнейшие открытия.
5. **«Сохранить приватные данные»** по отдельному подтверждению скачивает
   `vision-private-approval-evidence.json` только на ПК. Он содержит
   номера заказов, артикулов, тексты сообщений, имена файлов:
   **не отправляйте его в публичные чаты, GitHub, облачные сервисы**.
6. **«Анонимный отчёт обхода»** сохраняет JSON без номеров заказов,
   авторов, текста и имён файлов для анализа работы алгоритма.

Расширение **не загружает содержимое вложений**: разрешённые параметры
их чтения ещё не проверены. Сохранённые имена/ID дают точку привязки
для следующей строго локальной стадии. Бейдж с числом сообщений —
фильтр на открытие, а не доказательство найденного дефекта.
Обучение и допуск к печати остаются выключены.

Ограничения: не более 100 согласований на страницу заказа, не более
1500 сообщений в одном окне, один активный обход в текущей вкладке,
таймаут открытия 16 с. Если другая модалка уже открыта, обход не
закрывает её и требует ручной проверки. Для перехода между разными
заказами пока откройте страницу очередного заказа; скрипт проходит
все подходящие артикулы **внутри неё**.


## v0.1.3 — чтение замечаний дизайнера, сообщений и оригиналов вложений

При нажатии **«Автообход согласований >1»** расширение на
`http://testgifts.local/private/order/<номер>` выполняет:

1. Для каждого артикула с бейджем >1 штатным образом открывает
   `a.j_maketadjusting` и, при необходимости, вкладку `Обсуждение`.
2. Считывает именно **текущие отмеченные дизайнером** флажки
   `input[name="ma_problem[]"]:checked` с кодом, текстом,
   видом нанесения и местом печати из ближайшего блока.
   Остальные 25 возможных причин не считаются ошибками.
   История **«Добавлены проблемы»/«Удалены проблемы»** хранится
   отдельно, чтобы сохранилась последовательность исправлений.
3. Сохраняет все пользовательские реплики и системные события
   по порядку, их время, текст, исходные имена и `data-id`
   прикреплённых файлов в приватную память этой страницы.
4. После обхода автоматически делает последовательные **GET**
   только в `/ajax/gifts/order?action=download_maketadjusting_attachment&id=<ID>`.
   Этот URL выведен из сохранённого в источнике
   `OrderEmployer.config.downloadMaketAdjustingAttachmentUrl`
   и `idParam`. Доступа к исходному серверу в CI **нет**:
   реальный ответ ещё предстоит подтвердить.
5. Проверяет исходный URL/домен, запрещает редиректы, HTML вместо
   PDF/PSD/картинки, необычные расширения, опасные пути,
   исполняемые файлы; ограничивает ответ до **16 МБ на файл**.
   Неподдерживаемый ответ = **MANUAL**, не подмена обучающим файлом.
6. Укладывает подтверждённо считанные байты в локальные ZIP-части
   `vision-private-approval-attachments-part-0001.zip` и далее.
   Лимиты: 64 вложения на заказ, до 12 файлов/часть, до 24 МБ
   на одну часть. Внутри `manifest.json` — связь
   артикул/сообщение/файл, оригинальное имя, размер, сигнатура,
   SHA-256 **если поддерживается браузером**.
   Chrome может запросить разрешение на несколько скачиваний.
7. Нажмите **«Сохранить приватные данные»**, чтобы отдельно
   выгрузить все тексты сообщений и текущие проблемы в
   `vision-private-approval-evidence.json` с результатами чтения
   вложений. Для диагностики без персональных данных используйте
   **«Анонимный отчёт обхода»**.
8. **«Повторить скачивание вложений»** повторяет только чтение
   файлов в случае сбоя браузерной загрузки.

**Частная информация:** ZIP и приватный JSON могут включать
макеты заказчиков, персональные данные и коммерческие сведения.
Храните только на доверенном локальном ПК; не публикуйте в GitHub,
Issues, Actions, общедоступных чатах и облачных сервисах.
Скрипт не вызывает POST, не загружает файлы наружу и не обучает
модель без экспертной проверки соответствия версии макета,
технологии и ROI. Слишком большие/неизвестные вложения
остаются **MANUAL**.


## v0.1.4 — защищённые лимиты ZIP и SHA-256 на HTTP (18.11.2026)

Это обновление сохраняет функции v0.1.3, разрешения и режим локального хранения.

- Лимит `maxFiles` теперь действует до загрузки вложений. Некорректные
  числовые лимиты (NaN, дробные значения, строки) отвергаются до GET.
- SHA-256 исходных байтов рассчитывается также на HTTP-странице
  `http://testgifts.local`: если `crypto.subtle` недоступен, применяется
  локальный SHA-256, сверенный с Node.js crypto и стандартными векторами.
  Хеш устанавливает идентичность байтов, не подлинность источника.
- Номер расширения в Chrome — 0.1.4; та же версия видна в панели заказа.
- Чтобы обновить, скачайте новый ZIP, распакуйте поверх папки расширения,
  откройте `chrome://extensions` и нажмите «Обновить», затем перезагрузите
  вкладку заказа.

Ссылка: https://tohaa28.github.io/gifts-layout-workbench-vision/vision-local-lan-extension.zip

**Проверяйте 0.1.4 в Chrome:** пока CI-публикация не закончена, ссылка
может возвращать предыдущую сборку. Приватные макеты и обсуждения не
отправлять в публичный GitHub. Реальный ответ сервера, версия PDF,
физические размеры и экспертные ROI ещё не подтверждены;
`training_ready=false`, `production_approved=false`.


## v0.1.5 — автоматический обход прямо со страницы списка заказов

**Только тестовая сеть.** Полная инструкция:
docs/VISION_LIST_APPROVAL_AUTOSCAN_RU.md.

1. Обновите расширение на 0.1.5, нажмите «Обновить» на
   chrome://extensions и перезагрузите testgifts.local.
2. Откройте http://psk.testgifts.local/devorders в авторизованном
   браузере; при необходимости настройте фильтры списка.
3. В панели Vision Check нажмите
   **«Собрать согласования из всех заказов»**.
   Это новая рабочая команда; старая «Найти обсуждения» остаётся
   только структурным анализатором и **не** выгружает тексты.
4. На каждую видимую в таблице уникальную карточку расширение создаёт
   временную неактивную вкладку заказа. В ней последовательно открывает
   исключительно штатные «Согласование макета» с цифрой **2 или больше**,
   читает тексты переписки, исторические события и **только текущие
   отмеченные** ошибки дизайнера. После чтения закрывает свою вкладку.
5. Архивы вложений сохраняются локально в
   vision-private-approval-attachments-part-XXXX.zip;
   тексты **каждого заказа отдельно** —
   vision-private-approval-evidence-<номер>.json.
   Скриншоты из g-gallery.shadowRoot читаются по проверенным
   URL тестового файлового сервера, только если они принадлежат
   текущему заказу и артикулу. Навигационные миниатюры и аватары
   не включаются. Проверьте разрешение Chrome на несколько загрузок.
6. Кнопка **«Остановить согласования»** завершает текущий заказ
   и останавливает обход. Повторный старт продолжает очередь.
   «Отчёт согласований JSON» сохраняет анонимные статусы и счётчики.
   Приватные JSON и ZIP **не загружайте в общие чаты и GitHub**.

Расширение запрашивает три узких host-permissions:
psk.testgifts.local (список), testgifts.local (заказы),
files.testgifts.local (изображения только из подтверждённого каталога
согласований). Для фоновых вкладок требуется разрешение tabs.

Ограничения: система не выполняет POST, не меняет чужие согласования,
не ставит обучающие метки и не подтверждает годность макета. При HTTP
отказе либо неизвестной структуре результат MANUAL. Реальная
аутентифицированная загрузка с тестового сервера должна быть проверена
на месте; синтетический Chromium CI не устанавливает подлинность ответа
testgifts.local. Для обучения необходимы подтверждённая версия PDF,
метод печати, размеры/ROI и независимая экспертная оценка.

## v0.1.7 — переписки и сведения заказа сохраняются автоматически (M3.23)

**Исправление:** временная вкладка заказа ранее закрывалась после запуска
скачивания JSON через `<a download>`, поэтому часто сохранялись ZIP
с вложениями, а переписки отсутствовали. Теперь JSON скачивает
`chrome.downloads.download` из фонового сервис-воркера; прежде чем
подтвердить успех и закрыть временную вкладку, расширение проверяет
завершение Chrome-загрузки (`state=complete`).

После кнопки **«Собрать согласования из всех заказов»** на
`http://psk.testgifts.local/devorders` создаются:

- `vision-private-approval-evidence-<номер>-raw.json` — **резервная**
  полная копия переписки и сведений заказа ДО загрузки вложений.
- `vision-private-approval-attachments-<номер>-part-0001.zip` и
  дополнительные части — вложения и скриншоты с ID сообщения/артикула,
  SHA-256, размером байтов, исходным именем.
- `vision-private-approval-evidence-<номер>.json` — **окончательный**
  JSON после чтения файлов: вся переписка, авторы с исходными именами,
  даты, сообщения, системная история, отмеченные проблемы и текст
  описаний дизайнера, пути ZIP-частей, SHA-256, статусы отсутствующих
  вложений. Это **основной** файл для обучения/разбора.

Каждый JSON содержит `order_facts`: номер и внутренний ID заказа,
отображаемую дату, имя и сведения клиента из шапки, историю статусов,
а для каждого артикула — исходный ID, код, название, описание,
количество/цены, текст требований к нанесению, ID задач нанесения
(при наличии), счётчик согласований. Исходные сообщения содержат
`author_name` и `author_display_text` **без обезличивания**,
а также последовательность, тип и `native_comment_id`, когда он есть.
Проблемы из текущих флажков не смешиваются с событиями истории их
добавления/снятия; это разные факты.

Панель списка показывает число успешно сохранённых **итоговых JSON**,
только резервных копий и заказов без сохранённой переписки. В анонимный
диагностический отчёт добавлены булевы статусы `raw_evidence_saved` и
`final_evidence_saved`. Отсутствие подтверждения Chrome не считается
успехом. Для ручного запуска в карточке заказа сохраняется кнопка
**«Сохранить приватные данные»**.

Права расширения: `tabs`, `downloads`; только три прежних локальных
тестовых HTTP-домена. Нет POST, внешней синхронизации, передачи в GitHub
или включения автоматического обучения. Имена участников теперь
сохраняются в приватных локальных исходниках на явный запрос
пользователя. Обновить ZIP и расширение в `chrome://extensions`,
перезагрузить страницу списка заказов.

Для объединения всех заказов в локальный обучающий корпус:
`python tools/vision_approval_training_corpus.py --input-dir <каталог-загрузок> --output <новая-папка>`.
Конвертер автоматически выбирает **итоговые JSON** и не считает
`-raw.json` дублирующим заказом. Извлечённые сведения о заказах,
артикулах и именах авторов попадают в соответствующие таблицы корпуса.
`training_ready=false` до экспертной проверки ревизии/ROI.
