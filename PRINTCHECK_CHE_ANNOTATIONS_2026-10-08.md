# PrintCheck — пользовательская разметка `che.pdf` (2026-10-08)

Это не финальная проверка макета и не техническое заключение о каждом отмеченном участке. Пользователь вручную отметил **10 мест**, которые, по его мнению, не соответствуют ТТ. Отметки намеренно неполные и должны использоваться как *sparse review anchors*, а не как полный перечень дефектов.

## Файл

- PDF: одна страница, CorelDRAW 2025, размер страницы 37.05×37.05 мм.
- В PDF содержится один встроенный растр **354×354 px**, размещённый **30×30 мм** (около **300 dpi**), и **10 отдельных красных векторных кружков по 0.1 мм**.
- Источник растра в предыдущем тесте Макетной показывал **1048 dpi**. PDF из Corel — пониженное разрешение и не годится для точной автоматической аттестации порогов 0.10/0.20 мм.
- Оригинальный файл рисунка в этой контрольной разметке не содержится в прежнем разрешении. Не подменять его рендером PDF, увеличенным до 1048 dpi.
- Сам пользовательский bitmap/PDF не публикуется в публичном репозитории. Сохраняются только нормализованные координаты и описание.

## Дополнительная проблема v24, воспроизведённая на синтетической геометрии

`positiveCircleProbe()` выбирает только **одну позицию на connected missing-компоненту**. Резервный однопиксельный контроль запускается, только если SWT во всей компоненте ничего не нашёл. Для длинной линии, состоящей из сначала 2-px, затем 1-px отрезка, SWT возвращает кандидата на 2-px участке, но может пропустить продолжение 1-px. В тесте маркер ставится на переходе, а не в середине наиболее тонкого отрезка.

Перед следующей функциональной сборкой:
1. Получить original high-resolution logo, соотнести координаты.
2. Измерить реальную локальную толщину/ширину в нескольких ROI из разметки.
3. Рассмотреть дополнение fallback на **непокрытых SWT подотрезках той же компоненты**, не распространяя маркеры на обычный контур.
4. Проверять отрицательные пробелы отдельно; v23/v24 negative не изменять без реальных свидетельств ошибки.
5. Добавить регрессию на переменную толщину и на marker location, плюс старые golden tests.
6. Не публиковать новый алгоритм, пока он не лучше предыдущего на реальном входе и не проходит CI.

На момент этого документа **v24 остаётся опубликованным**, обновлений кода нет. Настоящие места несоответствия ещё не установлены: это обозначенные пользователем зоны для проверки.
